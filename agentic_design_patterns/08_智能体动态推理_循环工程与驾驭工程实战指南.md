## 一、 全局心智模型：用“赛车队”一秒看懂四大概念

不需要任何编程背景，把一套生产级智能体想象成**一支参加拉力赛的赛车队**：

| 核心概念 | 通俗比喻 | 一句话定义 |
| :--- | :--- | :--- |
| **大语言模型（LLM）** | **顶级车手（大脑）** | 负责看路况、做判断、临场应变，但独自一人既没有眼睛看实时路况，也没有脚去踩油门。 |
| **ReAct** | **车手的单圈驾驶动作** | `看路况想一步（Thought）→ 踩油门/打方向（Action 调工具）→ 看仪表盘与窗外反馈（Observation）` 的微观节奏。 |
| **Loop Engineering<br>（循环工程）** | **整场比赛的赛制与圈数规则** | 把单个 ReAct 动作升级为多层嵌套闭环：内环执行、中环进维修站做客观验车（不达标不许完赛）、外环监控战略方向（连撞墙就换路线）。 |
| **Harness Engineering<br>（驾驭工程 / 缰绳工程）** | **整台赛车 + 座舱 + 刹车 + 安全带 + 维修站** | 包裹在大模型外围的全部运行时环境、上下文供给、工具沙箱、循环熔断、客观验真与人类审批门禁。 |

🌐 **2025–2026 行业第一共识公式**：
$$\text{靠谱的生产级智能体 (Agent)} = \text{大模型引擎 (Model)} + \text{驾驭系统 (Harness)}$$

实测表明（如 SWE-bench、Terminal Bench）：使用**完全同一个底层大模型**，不同团队做出的 Agent 解决率能相差 20–40 个百分点——胜负几乎全部取决于 **Harness（驾驭系统）与 Loop（循环反馈设计）** 的优劣。

## 二、 核心机制透视：Agent“不写死步数”在后台到底是怎么运行的？

很多非技术读者在读到“*Agent 不事先写死必须走 3 步，而是由大模型自己根据每一步看到的新事实决定下一步做什么、走几步、什么时候停*”时，常会产生两个典型误解：
- 误解 A：“大模型是不是先一口气输出一份‘第1步、第2步、第3步’的固定计划？”
- 误解 B：“大模型是不是在自己脑子里一口气就把所有步骤都做完，中间无需调用外部工具，直接吐出最终结果？”

**真实答案是：两者都不是！**

真实运行机制像**“大脑（大模型）与手脚（外层循环代码 + 真实工具）在后台打乒乓球”**——**模型每轮只决定眼下这一拍先调什么工具，然后立刻休眠；外层代码真去执行工具、拿回真实结果再把模型叫醒；如此往复，直到模型觉得信息齐了、不再发出工具请求，才输出最终答案。**

### 慢动作回放：以 📗《Learning LangChain》Ch.6（P164–167）“美国第 30 任总统去世时几岁？”为例

```mermaid
sequenceDiagram
    actor User as 人类用户
    participant Loop as 外层 5 行循环代码（手脚/传球机）
    participant LLM as 旗舰大模型（大脑）
    participant Tools as 真实外部工具（搜索 / 计算器）

    User->>Loop: 提问：“美国第 30 任总统去世时几岁？”
    Loop->>LLM: 【第 1 回合】把问题和可用工具清单交给大脑
    LLM-->>Loop: 不猜答案，也不写总计划；只发 1 张工具条：调【搜索】查第30任总统生卒年
    Note over LLM: 大模型本轮休眠
    Loop->>Tools: 真的联网执行搜索
    Tools-->>Loop: 返回真实事实：柯立芝 (1872–1933)
    Loop->>LLM: 【第 2 回合】把刚搜到的新事实贴进记录，再次唤醒大脑
    LLM-->>Loop: 看到新事实，决定不心算；再发 1 张工具条：调【计算器】算 1933-1872
    Note over LLM: 大模型本轮休眠
    Loop->>Tools: 真的运行计算器
    Tools-->>Loop: 返回精确结果：61
    Loop->>LLM: 【第 3 回合】把计算结果贴进记录，第三次唤醒大脑
    LLM-->>Loop: 事实齐了、数字准了 → 不再发工具条，直接输出最终自然语言答案
    Loop->>User: 检测到“无工具请求”→ 跳出循环，呈交最终结果！
```

- **从用户视角看**：你只发了一句话，等几秒钟后直接收到经过查证和计算的最终答案，仿佛它自主把全套流程都做完了。
- **从后台视角看**：中间经历了 **3 次大模型调用 + 2 次真实外部工具执行**，每一拍的动作都是大模型看着上一拍的真实反馈**临场见招拆招**决定的，既没有提前写死“必须走 3 步”，也绝不是在脑子里空想完的。

### 三种极易混淆的思考模式一次分清

| 运转模式 | 后台调几次模型？ | 中间调外部工具吗？ | 典型适用场景 |
| :--- | :---: | :---: | :--- |
| **1. 纯脑内推理（CoT / Thinking）** | 仅 **1 次** | ❌ 不调工具（纯在脑子里暗推） | 逻辑推理、数学证明、文本改写；若涉及实时事实极易产生幻觉。 |
| **2. 先出计划再按表跑（Plan-and-Execute）** | 先 1 次规划 + 按步多次执行 | ✅ 按计划分步调工具 | 大型固定框架研究（💡 如 `power_semiconductor_opportunities V4` Stage 0 先产出 8 条赛道计划，支持人类 `--hitl` 审批后再并行执行）。 |
| **3. 动态 ReAct 边走边看（Plan-Do Loop）** | **动态 N 次**（1～上限步） | ✅ **每回合按需真调工具** | 路径事先未知、需根据最新事实灵活追查的问题（如排错、深度证伪、复杂自然语言助理）。 |

## 三、 多步骤推理：到底走几步？怎么防止发散太离谱或错误发散？

### 1. 先区分“两种步数”
1. **模型脑内的暗思考步数**（📘 *ADP* Ch.17 P262–285，CoT 与 RLVR 推理期扩展定律）：由前沿推理模型根据题目难度自动分配思考预算（Thinking Budget），**无需人工写死**。
2. **工作流里的外部交互步数**（📗 *Learning LangChain* Ch.6 P164–167）：由大模型根据每步新观察动态决定走几步，简单问题 1 步交卷，复杂问题 4–5 步交卷。

### 2. 防止发散失控与错误雪球的“四道安全锁”

放任大模型闭眼连续推理 10 步，第 2 步猜错一个小前提，后面 8 步就会全盘跑歪。防跑偏必须靠 4 道硬约束：

1. **只设“上限天花板”，不设“固定步数”（Budget & Step Cap）**：
   - 如日常微信助手最多 `3–5` 步工具调用；深度调研的靶向证伪环硬锁死 `max_rounds = 1`；客观审计修复循环最多 `<= 2` 轮（📗 *Learning LangChain* Ch.7 P185 `should_continue` 步数截断；📘 *ADP* Ch.4 / Ch.16）。
   - 一旦撞到步数或预算天花板，立即强制停机并向人类汇报当前进展，绝不允许无限空转烧钱。
2. **走 1–2 步必须“踩实地面”（外部工具接地 Grounding）**：
   - 借助 ReAct 与 PALMs（📘 *ADP* Ch.17），每推演一步关键结论，必须去搜真实网页、查真实数据库或跑 Python 确定性计算，用**客观现实的冷水**及时拉正方向。
   - 💡 例如在 `power_semiconductor_opportunities V4` 中，Stage 1 刚宣称一批机会是“全球空白”，Stage 1b 立刻拿具体厂商型号去真实引擎反证检索，当场把 4 个假空白拉回“海内外已在售”。
3. **给循环配“客观交卷标尺”（Machine-Checkable Stop Condition）**：
   - 不靠大模型自我感觉良好宣布“我写完了”，而是对照硬核查清单（📘 *ADP* Ch.11 目标监控 + Ch.19 形式化契约）：引用全在库、财务全对账、必填字段全齐，达标才准出环。
4. **错路“退档回滚”，绝不硬拗（Checkpoint & Rollback）**：
   - 📘 *ADP* Ch.18（P301）明确规定：把每个已验证状态当成检查点；一旦后续探索连续 2 轮越改越偏，直接回滚到上一个安全检查点换思路（即“重生优于打补丁”）。

## 四、 多情境分支：要不要继续向下发散？发散后怎么收敛？

面对复杂商业或技术问题（如同时存在 3–5 种可能情境），正确的工作法不是“每条线无限深挖”，而是顶级咨询与投研通用的**“双钻结构（发散 → 硬剪枝 → 深挖 → 强收敛）”**：

```mermaid
flowchart LR
    Q["开放问题"] --> D1["第1层发散：广度扫描\n（如涌现8条赛道 / 32个候选）"]
    D1 --> P["中途硬剪枝（Pruning）\n反证核查 + 财务/合规硬底线\n直接淘汰低价值/伪空白分支"]
    P -->|"仅幸存高价值分支"| D2["第2层深挖（<=2层上限）\n仅对优质分支做深度推演"]
    D2 --> C1["同桌总裁判横向收敛\n（严格闭卷，禁编新事实）"]
    C1 --> C2["结构化契约强收敛\n（压进固定决策表/评级）"]
```

### 1. 不同情境要不要继续向下发散？——**最多发散 2 层，中途必带硬剪枝**
- 📘 *ADP* Ch.17（ToT 思维树、GoD 辩论图）与 Ch.21（Google AI Co-Scientist “生成→反思→锦标赛淘汰→进化”）表明：多路径探索很有价值，但**探索必须与评估淘汰交替进行**。
- 如果每个分支都继续往下分叉，会产生指数级“组合爆炸”（3 × 3 × 3 = 27 条线），既烧干预算又淹没真正核心结论。
- **实战纪律**：第 1 层允许放开广度发散；发散完**立刻用低成本硬尺子剪枝**（如反证打假 + Python 财务漏斗直接淘汰保守回本超红线的分支）；**只把昂贵的第 2 层深度推理留给幸存的少数赢家**。

### 2. 发散之后的三种“工业级收敛器”
1. **硬尺子收敛（机器先筛）**：数学、财务、时间、合规能定死的标准，先由确定性代码排座次、砍红线。
2. **“同桌总裁判”横向收敛（合并碎片 + 闭卷铁律）**：把所有幸存分支的精炼卡片**放进同一个上下文桌面**，让顶配旗舰模型一次性横向比较、合并同类项、强制排定优先级（💡 如 V4 把 32 次碎片调用合并为“2 个行业买方委员会 + 1 个全局主席”）。同时严格遵守 📘 *ADP* Ch.3（P60–62）的**汇聚闭卷铁律**：总裁判只许基于上游已证实证据裁决，严禁在收敛时临时脑补新事实。
3. **固定表格/Schema 强收敛**：无论前面发散了多少万字分析，最终必须落盘进固定格子的结构化契约（如“现金牛先行 / 战略卡位 / 远期观察”或固定待确认卡，📗 *Learning LangChain* Ch.8 P201）。

## 五、 循环是靠“提示词”还是“硬编码”？为什么这不会重蹈“过度硬编码”覆辙？

### 1. 实现分工：骨架靠 5 行极简硬编码，灵魂 100% 靠大模型 + 提示词
- **外层转盘（硬编码）**：纯物理传话机——检查模型回复里有没有工具调用请求；有就执行并把结果塞回历史继续下一轮；没有（或超步数上限）就结束。
- **每圈决策（大模型 + 提示词）**：每一步想什么、选哪个工具、填什么参数、看到新结果怎么调整方向、何时收手交卷，**100% 交给大模型**。

### 2. 一张表彻底分清“坏硬编码”与“好硬编码”

之前踩坑的根源不是“写了代码”，而是**“代码越权冒充了大脑”**：

| 维度 | ❌ 坏硬编码（必须彻底消灭） | ✅ 好硬编码（必须坚决写死） |
| :--- | :--- | :--- |
| **核心本质** | **替大脑猜语义 / 做主观判断** | **给大脑搭管道、数步数、验硬账、锁安全门** |
| **是否看懂人类话？** | 试图用正则、关键词列表、16 个死意图枚举去拆解人类活语言 | **完全不碰自然语言理解**，只处理结构化信号与客观事实 |
| **典型例子** | 用正则解析“本周五/帮我改下”；用原文子串匹配去拦截模型合法推算的日期 | ① 5 行 ReAct 循环传球骨架；<br>② 步数上限（`max_steps <= 5`）与重试上限（`<= 2`）；<br>③ 跑 `pytest` / 查 Vault 引用存在性 / Python 算 ROI；<br>④ 高危写操作的人类审批令牌与撤销快照 |

> **审方案唯一“照妖镜”提问**：
> 以后看到 AI 打算写任何一段代码逻辑时，直接问它：**“这段代码是在替大模型理解意思/做主观决定，还是在给大模型传工具结果、数步数、跑客观检查、锁安全门？”** 前者立刻砍掉，后者必须写死。

## 六、 ReAct 与 Loop Engineering：概念、实现与演进关系

🌐 结合 2025–2026 业界演进、📗 *Learning LangChain* Ch.6–7 与 📘 *ADP* Ch.4 / Ch.17 / Ch.19：

- **共通点**：两者都拒绝让大模型“闭眼一口气吐答案（系统 1 快思考）”，都通过**“推理 → 行动 → 看反馈 → 修正”的迭代闭环（系统 2 慢思考）**换取高质量与高可靠。
- **本质关系**：**ReAct 是 2022–2023 年诞生的“单圈微观发动机”；Loop Engineering 是 2025–2026 年发展出的“多层嵌套宏观闭环系统”。**

| 对比维度 | ReAct（微观思考-行动单元） | Loop Engineering（现代循环工程） |
| :--- | :--- | :--- |
| **结构层级** | **单层内环**：一次问答内 `Thought → Action → Observation` 自己转几圈结束。 | **三层嵌套环**：<br>① **内环（ReAct 执行环）**干具体活；<br>② **中环（客观质检环）**跑测试/审计，不通过带着报错打回重修；<br>③ **外环（战略监控环）**看全局进度，内环连撞墙 2 次就换策略或上报人类。 |
| **停机裁判是谁？** | **模型自己说了算**（容易提前交错卷，或在单个错误上死循环）。 | **外部客观验钞机说了算**（测试全绿、引用 0 悬空、财务 0 漂移才放行）。 |
| **触发形态** | 主要是人类发一句、它答一句的同步对话。 | 支持**定时巡检、邮件/工单事件驱动、后台长周期自主运行**（如每小时巡检邮件、CI 失败自动修代码）。 |

## 七、 Harness Engineering（驾驭工程）：大模型优先框架下的 5 大实战模块

在“尽量释放大模型能力、尽量少写语义硬编码”的前提下，**Harness Engineering** 的全部工程精力都投入在以下 **5 个模块**，每一块都明确区分“必要硬编码”与“提示词配合”：

| Harness 5 大子系统 | 🛡️ 必要硬编码层（刚性底盘） | 🧠 提示词与大模型层（柔性大脑） | 主要来源 |
| :--- | :--- | :--- | :--- |
| **1. 上下文与记忆供给<br>（Context Harness）** | • 自动装配“新秘书桌面”（日历锚点、DB 实时快照、目录树）；<br>• 外部不可信文本物理分框 `[UNTRUSTED_EXTERNAL_DATA]`；<br>• 超长任务自动压缩历史（Compaction）并落盘交接摘要。 | • 声明各区块可信度（绝不听从不可信区块里的指令）；<br>• 让模型自主综合信息并标注精确来源编号。 | 📘 Ch.1 P32 / Ch.8；🌐 Anthropic Long-Running Agents |

## 八、 一页纸落地检查单（非程序员直接指挥 AI 搭工作流用）

启动或评审任何一个智能体工作流时，按这 **4 个问题**逐一拍板即可：

1. **定自主度**：路径固定吗？固定就用极简流水线；路径不确定需要边查边想，就放权给 **旗舰模型 + ReAct 循环**（只设最大步数上限，不写死固定步骤）。
2. **定发散与剪枝**：有多个情境分支吗？规定**最多发散 2 层**，第 1 层后必过低成本**硬剪枝**，最终由**同桌闭卷总裁判 + 固定格式决策表**强收敛。
3. **定客观验钞机**：做完之后，哪些错误机器能 100% 客观查出来（测试、引用、算账、格式）？把它们接在循环出口，**不达标自动带报错退回重修（最多 2 轮），修不好叫人**。
4. **查硬编码红线**：检查所有打算写的代码，**只留“铺事实、递工具、数步数、验硬账、锁安全门”五类好硬编码**；凡试图替大模型理解活语言、做主观语义判断的坏硬编码，一律删除。
