# 防 AI 偷懒借口与测试反模式自查表 (Anti-Rationalization Matrix)

本表源自 `obra/superpowers` 与 `addyosmani/agent-skills` 生产工程实践。当你在编码或修 Bug 过程中脑海里浮现以下“省事念头”时，**立即踩刹车，按右侧标准纠正**：

| 常见偷懒/违规念头（危险信号 🚨） | 为什么这是陷阱？ | 强制执行的正确动作 ✅ |
| :--- | :--- | :--- |
| *“这个改动很简单，我先把 `src/` 写完再顺手补个测试吧”* | 一旦先写了业务代码，后补的测试 90% 会顺着刚写的实现逻辑去写断言，沦为同源串谋假测试，且你从没见过它失败过 | **停手！** 先写/先派 `blind-test-author` 跑出红灯测试，亲眼看到预期报错后再写业务代码 |
| *“为了跑得快，我把 SQLite 数据库方法也 `MagicMock` 掉吧”* | Mock 掉数据库后，表名拼错、事务没提交、唯一索引冲突、SQL 语法错误全部测不出来，上线即崩 | **用真实内存库或 `tmp_path` 临时 SQLite 文件**跑完整读写，只 Stub 最外层付费/外部 HTTP 网关 |
| *“这个测试一直不过，我把测试里的期望值改成当前代码返回的值就绿了”* | 这是最严重的**篡改标尺欺骗人类行为** | **严禁私自改测试凑绿灯！** 认真修 `src/`；若确属需求契约矛盾，停下把冲突行号摆给人类拍板 |
| *“刚改了一行小字段，上次跑过 `pytest` 绿了，这次不用再跑直接汇报完成吧”* | “应该能过”不等于证据；最后一步微调最容易漏导入或打破其它模块契约 | **必须在当前汇报前重新跑一遍完整测试命令**，拿到新鲜的 Exit Code 0 |
| *“这个外部拉取报错很烦，加个 `except Exception: return []` 就稳了”* | 线上密钥失效或接口变更时，系统表面不报错却静默丢光所有业务数据，排查极度痛苦 | 记录带上下文的 `logger.exception(...)` 并返回显式错误状态或触发告警，绝不静默吞错 |
| *“我直接在这段业务函数里拼一段临时 Prompt 调模型，省得去改 `prompts.py`”* | 打破了 **🔴 红区物理隔离**，导致人类架构师只读 `prompts.py` 时漏看隐藏在业务深处的野生提示词 | 把提示词统一抽入集中式 `prompts/` 红区文件，业务层只负责传结构化上下文变量 |
