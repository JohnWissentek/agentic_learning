# 个人独立开发者生产级交付工程宪章 (Solo Production Guardrails)

本规则面向「1 名独立开发者/架构师 + AI Agent」协作模式，旨在消除“一次性生成海量代码导致人工审码瘫痪”与“AI 同源串谋假测试”，确保交付生产级（Production-Grade）软件。详细工程体系见工作区 `solo_agentic_engineering_guide/`。

---

## 铁律 1：禁止未经批准的整包倾倒，强制「契约先行 + 垂直薄切片」

1. **严禁一次性倾倒全量业务代码**：面对新项目或跨模块大功能时，禁止一上来生成上千行完整实现。必须先对齐模糊边界，优先交付 **Slice 0（🔴 红区核心契约）**，再按每片 **150～300 行有效代码** 的端到端「垂直薄切片（Vertical Slice）」逐片推进（详细流程激活 `spec-thin-slice` 技能）。
2. **重生优于打补丁（Regeneration > Patching）**：同一薄切片若连续修改 2 轮仍出现回归破坏或逻辑绕圈，应主动停止叠补丁，提示用户补齐边界条件后基于干净契约重新实现该切片。

---

## 铁律 2：🔴 红区代码物理隔离（支撑人类「只读 10% 管住 95%」）

为确保人类开发者无需通读几千行胶水代码即可掌控全局，必须在代码结构上物理隔离以下 **🔴 红区文件**（总行数压控在全项目 10% 以内）：

1. **数据契约集中化**（如 `schemas.py` / `types.ts`）：所有跨模块枚举、Pydantic/JSON Schema、字段默认值集中定义，禁止在编排逻辑中传递无类型裸字典。
2. **提示词集中化**（如 `prompts/`）：所有大模型 System Prompts 必须集中定义，**严禁在业务函数内部零散硬编码野生提示词**。
3. **安全与资金门禁独立化**（如 `guard.py` / `auth.py`）：白名单校验、人类确认令牌（HITL Token）验签、金额/关键数字确定性核验、敏感信息脱敏必须封装为独立纯函数，严禁散落在路由或 UI 代码中。

---

## 铁律 3：读写隔离 TDD 与「测试断言神圣不可篡改」

1. **先红灯，后写码（No Production Code Without Failing Test First）**：新增核心业务逻辑或修复 Bug 时，优先通过独立上下文（如 `blind-test-author` 子智能体或 `red-green-tdd` 技能）基于契约与中文验收矩阵编写黑盒测试，并亲眼验证测试因预期原因失败（Red）。
2. **绿灯阶段锁死 `tests/`**：在编写或修改 `src/` 业务代码使测试变绿（Green）的过程中，**严禁擅自修改、删除、注释、`skip` 或弱化 `tests/` 中的既有断言来“凑绿灯”**。若确因需求契约变更导致测试过时，必须暂停并明确向用户列出拟修改的测试行号，获批后方可改动。

---

## 铁律 4：生产级防御编码基线（Production Safety Baseline）

任何准备进入主干的业务代码必须默认满足以下生产底线：

1. **入口幂等防重**：回调、轮询、队列消费及写库入口必须具备唯一标识去重或幂等保护。
2. **超时与有界重试**：所有外部 HTTP / LLM / 存储调用**必须显式设置 `timeout`**；重试循环必须有硬上限（如 `<= 2` 次），严禁无界死循环。
3. **零静默吞错**：**全仓严禁裸 `except: pass` 或吞掉异常伪装空结果**；异常捕获必须保留明确上下文日志或向上抛出受控错误。
4. **不可信输入隔离**：外部邮件、用户转发文本、上传附件默认视为不可信数据——先过确定性代码白名单与体积/解压上限检查，进入模型前用显式不可信边界标签包裹；高危写操作必经人类确认令牌或保留可撤销快照。
5. **密钥零硬编码**：严禁在代码、测试或日志中硬编码真实密钥；启动时对必需配置执行 Fast-Fail 强校验，外发消息前执行敏感词/密钥脱敏检查。

---

## 铁律 5：无当轮新鲜实证，严禁声称「已完成」（Verification Before Completion）

1. **证据先于结论**：在未于当前轮次实际执行测试套件、静态检查或探针脚本并读取完整退出码前，**严禁使用“应该没问题了”“理论上已修复”“已完成”等断言**。
2. **交付必贴实证**：每次切片完工或 Bug 修复汇报时，必须附上实际运行的命令、退出码（Exit Code）以及通过/失败用例计数；拒绝一切未经验证的口头保证。
