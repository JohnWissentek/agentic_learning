# 防同源串谋与高可读黑盒测试编写准则 (Anti-Collusion Testing Rules)

当创建、修改或审阅任何测试文件时，必须严格遵守本准则，杜绝 AI「照着有缺陷的业务代码写同义反复假测试（Tautological Tests）」，并确保人类开发者能在 **60 秒内仅凭测试名与 `assert` 行审完测试质量**。

---

## 1. 个人开发者测试配比（Testing Trophy，拒绝无效单测膨胀）

1. **主力写「模块级黑盒契约 / 集成测试」（占 65%+）**：
   - 从模块的公开入口（Public Function / FastAPI `TestClient` / 状态图 `invoke`）喂入贴近真实的输入载荷；
   - **数据库用真实内存库或临时文件库（如临时 SQLite），严禁把数据库读写本身 Mock 成假返回值**；
   - 只允许对真正产生外部费用或外网副作用的最外层边界（如付费 LLM API、企业微信/邮件远端 HTTP 接口）注入确定性 Fake / Stub。
2. **精准写「高危纯逻辑单元测试」（占 25%）**：
   - 仅对金额计算、报价差额核对、权限白名单、加密令牌验签、日期排期推算、脱敏正则编写纯函数单测；
   - **禁止**为普通胶水转发、简单样板 CRUD 或前端静态结构编写脆弱的内部单测。
3. **极简写「端到端冒烟测试」（占 <= 10%）**：
   - 仅保留 2～3 条核心生死主干贯通验证，不用重型 E2E 去穷举业务分支排列组合。

---

## 2. 四大严禁触碰的「假测试反模式」

1. **严禁空洞断言（No Vacuous Assertions）**：
   - 禁止仅写 `assert result is not None`、`assert resp.status_code == 200` 或 `assert len(items) >= 0` 敷衍过关；
   - 必须精确断言核心业务字段的具体值、状态流转结果以及数据库目标表的前后行数/字段变化（DB Diff）。
2. **严禁绑死私有实现细节（Test Behavior, Never Internals）**：
   - 禁止直接导入测试 `_private_helper` 内部私有函数（高危纯算法除外）；
   - 禁止用 `mock.assert_called_once_with(...)` 去锁死内部辅助函数的调用顺序，除非该调用本身就是安全边界契约（例如：**“快捷指令路径必须保证 LLM 网关调用次数严格等于 `0`”**）。
3. **严禁只测正常路径（50%+ 预算给边界与禁令）**：
   - 任何功能模块的测试集中，**异常边界与安全禁令用例占比不得低于 50%**（必须覆盖：非白名单越权输入、重复事件幂等跳过、混合意图边界、空数据/坏格式文件兜底、未授权禁止写正式表）。
4. **严禁照抄实现逻辑算期望值**：
   - 测试中的期望值（Expected Value）必须写成人类一眼可读的字面常量（例如直接写 `assert diff_total == Decimal("-1250.00")`），严禁把生产代码里的公式复制一遍算期望值。

---

## 3. 60 秒人类速审友好排版（DAMP 原则）

1. **中文场景直译文档字符串**：每个测试函数顶部必须带一行清晰的中文业务说明，格式为：
   `"""[正常|边界|禁令] 当 <输入条件> 时，应 <预期结果>，且绝不 <禁止副作用>。"""`
2. **自包含可读（DAMP > DRY）**：测试代码宁可适当重复构造数据的几行代码，也不要抽取多层晦涩的测试基类或跳来跳去的全局隐式 Fixture；打开任意一个 `test_xxx` 函数，从上往下读 20 行必须能完整看懂 `Given（准备） → When（执行） → Then（断言）`。
