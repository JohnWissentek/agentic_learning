# 假期台账与余额自动重建方案（Excel 设定值 + API 对账写回）

> **版本**：V0.1（方案定稿待 PRD 确认；对应审计引擎待立项功能 F16「假期台账与余额自动重建」）
> **适用主体**：北京帕莫瑞科技有限公司 / 维恩科仪（北京）机械自动化设备有限公司
> **效力**：本文是技术方案，不创设权利义务。假期额度以 2026-08-21 确认版《考勤管理制度》及 HR 核定值为准。
> **红线**：余额变更须经员工/HR 确认后写入，不得静默扣减；审批同意一律人工，AI/系统不得自动通过。

> - 接口报文与调用时序：[企业微信 OpenAPI 参考](../reference/wecom_openapi.md)
> - 部署与定时任务：[部署与运维指南](../DEPLOYMENT.md)

## 1. 要解决的问题

企微的假期余额是一个**易碎的状态**：

- 修改假期类型规则 → 全员该假期余额按新规则**重发且不可恢复**；
- 后台「修改余额」直接改剩余值 → 不留推导过程，台账三列失衡（已出现实例：某员工年假发放 80h / 已用 109h / 剩余 51h；调休发放 16h / 已用 32h / 剩余 8h）；
- 谁改的、为什么改，事后无法复盘。

## 2. 核心原则：台账权威在引擎，企微余额是可再生的显示屏

> **企微应显示的余额 = 年度设定值（Excel）＋ 引擎核定充值（合格加班 1:1、在途调休分档）− 审批单已用（请假）− 被动抵扣（月上限 4h）**

等式右边四项全部有独立数据源、全部落库可追溯。任何时刻（包括误改设置导致企微余额重发之后），跑一次**重建任务**即可逐人算出应有余额并写回企微。企微余额从「怕丢的账本」降级为「可再生的缓存」。

## 3. 数据流

| 数据 | 来源 | 接口 / 方式 | 节奏 |
|---|---|---|---|
| 年度设定值 | HR 维护的 Excel（见 §4 模板） | 引擎导入命令，强校验后入库 | 每年一次 + 人员异动时 |
| 打卡记录 | 企微打卡 | `getcheckindata` | T-1 每日拉取 |
| 请假/出差/外出/加班/补卡单 | 企微审批 | `sys_approval_change` 回调 + `getapprovaldetail`，全量落库 | 实时回调 + 每日兜底拉取 |
| 企微当前余额 | 企微假期管理 | `getuservacationquota` | 每日对账 + 月度封账 |
| 修正写回 | 引擎 → 企微 | `setoneuserquota`（设定剩余值，0.1h 整倍数，remarks 填审计流水号） | 经确认后，清晨低峰窗口 |

权限前提：自建应用加入 `审批` 应用「可调用接口的应用」列表；频率限制 600 次/分钟。

## 4. 年度设定值 Excel 模板（HR 维护）

固定表头，一人一行，一年一个文件（如 `假期年度设定_2026.xlsx`），随花名册同目录版本留档：

| 列 | 示例 | 校验规则 |
|---|---|---|
| userid | ZhangSan | 必须与企微通讯录 / 花名册 JSON 匹配 |
| 姓名 | 张三 | 与 userid 交叉核对，防串行 |
| 年度 | 2026 | 与文件名一致 |
| 年假_小时 | 40.0 | ≥0，0.1h 整倍数（1 天 = 8h） |
| 调休期初_小时 | 8.0 | ≥0，0.1h 整倍数（跨年结转经 HR 核定） |
| 备注 | 工龄 3 年 | 可空 |

引擎导入时逐行强校验，任何一行不合规整个文件拒收（防止半份数据入库）。

## 5. 三个任务

### 5.1 日常核算（T-1，自动）
拉取打卡 + 审批单 → 核算合格加班、在途调休分档（≤2h 不计 / 2–4h=0.5 天 / >4h=1 天）、被动抵扣 → 生成余额变更明细 → 邮件/企微通知员工与 HR **确认** → 确认后 `setoneuserquota` 写回。写回纪律：该接口是**设定绝对值**，必须「先读当前余额 → 计算 → 写入 → 立即回读复核」，固定在清晨低峰执行，避免与并发请假单竞争。

### 5.2 月度封账对账（自动出报告，人工签认）
全员 `getuservacationquota` ↔ 引擎台账逐项比对；任何差异（含 HR 后台手工改动）列入对账报告。调休过期（当年用完、可延至次年前两月）在每年 2 月末封账时算出应清零额，经 HR 确认后写回。

### 5.3 全量重建（手动触发，兜底）
适用场景：误改假期类型规则导致余额重发、历史台账失衡、系统迁移。流程：Excel 设定值 + 全年审批单 + 引擎充值/抵扣流水 → 重算每人每假期应有余额 → 生成重建报告 → HR 签认 → 批量写回（remarks 注明「全量重建 YYYY-MM-DD」）。

## 6. 上线前置：期初核定（一次性）

现有企微台账已失衡，引擎上线前必须建立期初基准：

1. `假期余额` 页导出全量留档；
2. HR 逐人核定正确余额，填入年度设定值 Excel（调休期初列）；
3. 企微后台重新导入核定值（备注「2026-08 期初核定」）；
4. 引擎以此为台账起点，此后企微侧不再手工改余额——一切变更走引擎确认流。

## 7. 边界与不承诺

- `setoneuserquota` 只能修正**剩余时长**；企微界面「预计发放/实际发放/已用」三列的历史错乱无法修复，权威三列账以引擎报表为准，员工看剩余值即可；
- 请假扣减仍由企微原生完成（审批通过自动扣），引擎不重复扣，只对账；
- 薪资扣款（无酬缺勤公式）不由本方案代扣，引擎只出数，HR 人工执行。
