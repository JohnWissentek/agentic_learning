# 办公区 Wi-Fi 与蓝牙双重验证打卡系统技术方案

---

## 1. 方案概述与背景
为构建高可靠、防作弊的办公区考勤打卡机制，本方案基于**企业微信（WeCom）**原生考勤设备管理功能，设计了 **Wi-Fi BSSID 验证** 与 **BLE 蓝牙信标验证** 相结合的双重验证打卡方案。

为了在**不收集员工面部人脸特征数据（避开生物识别信息合规红线）**的前提下，解决传统 IC 卡/实体门禁卡存在的“代刷卡”和“未刷卡尾随出入”漏洞，系统引进了 **“Wi-Fi + 蓝牙 + 门禁刷卡”三合一交叉审计机制（Three-in-One Mutual Verification）**。

本方案旨在解决两个核心痛点：
1. **防止定位作弊与代打卡（防虚拟定位及代刷卡）**：利用物理路由器的 MAC 地址（BSSID）和实体蓝牙打卡器的高频 BLE 广播信号对门禁刷卡记录进行交叉核验。如果刷卡时间与手机 Wi-Fi/蓝牙在线时间不吻合，直接标记为异常。
2. **打卡容灾备份（高可用三选一）**：员工在办公区连接 Wi-Fi、靠近 3 个门中的任意蓝牙、或刷门禁卡，三种方式满足任意一种，系统即可自动对账并判定正常出勤，极大地提升了员工的打卡体验。

## 3. 网络拓扑与物理接线设计 (Network & Wiring Design)

针对**“办公室内不部署本地考勤电脑/服务器，所有设备直接通过办公室网络连入企业微信云端”**的实际情况，系统采用如下的云端中转架构：

```
  【 办公室物理现场 (LAN) 】                  【 云端 (Cloud) 】
  ┌────────────────────────┐
  │ 1. 门禁机 (ZK-T1)       │
  │    (网线/WiFi 联网)      ├───┐
  └────────────────────────┘   │
                               │
  ┌────────────────────────┐   │ 办公室网络    ┌─────────────────┐
  │ 2. 员工手机端          ├─ ─┼ ─ ─ ─ ─ ─ ─ ─►│  企业微信云服务器 │
  │    (感应 BLT1 蓝牙)     │   │ (Internet)    │  (WeCom Cloud)  │
  └──────────▲─────────────┘   │               └────────┬────────┘
             │                 │                        │
             │ BLE 广播        │                        │ OpenAPI
  ┌──────────┴─────────────┐   │                        ▼
  │ 3. BLT1 蓝牙盒子       │   │                ┌─────────────────┐
  │    (无源/仅广播不联网)  ├───┘                │   阿里云 ECS     │
  └────────────────────────┘                    │ (系统考勤中间件) │
                                                └─────────────────┘
```

### 3.1 刷卡门禁一体机：网线/WiFi 连入办公室路由器
* **联网物理布线**：
  - 将熵基 ZK-T1 或得力门禁机，通过**网线（RJ45接口）**或者直接连接**办公室的 WiFi 无线网络**。
  - 门禁机只要连通办公室网络，即可通过办公室宽带直接访问外网。
* **数据流向**：
  - 员工在门口刷卡时，门禁一体机通过办公室网络连接到**企业微信硬件云服务器（WeCom Cloud）**，将刷卡时间戳与卡号数据实时上传并备份至企微云端。
  - **办公室现场不需要运行任何考勤电脑**，仅需保证路由器正常联网即可。

### 3.2 蓝牙打卡盒子：手机网络中转
* **联网物理布线**：
  - BLT1 蓝牙盒子本身由于没有网络芯片，不需要接网线，也不需要连公司 WiFi，仅靠电池独立发射高频蓝牙信号。
* **数据流向**：
  - 员工走到门口时，手机上的企业微信通过蓝牙感应到盒子信号。
  - 手机自动通过**办公室局域网 WiFi（或手机移动流量）**，直接向企业微信云服务器发送打卡报文，实现云端签到。

### 3.3 阿里云 ECS 考勤中间件：API 自动对账
* **数据拉取与交叉勾稽**：
  - 运行在阿里云 ECS 上的考勤系统中间件后台（即本系统核心），通过企业微信 OpenAPI（例如 `/cgi-bin/hardware/get_device_data` 接口或事件回调）定期将云端企业微信中的“门禁刷卡日志”和“蓝牙打卡日志”同步回系统本地 PostgreSQL 数据库。
  - 考勤审计引擎在云端对拉取回的数据执行三维交叉比对，判定脱岗、漏刷卡尾随或代刷卡。

## 4. 系统配置步骤 (部署指南)

部署该系统分为三步：Wi-Fi MAC 采集、蓝牙设备绑定及规则配置。

### 4.1 步骤 1：采集并配置公司路由器 Wi-Fi BSSID（2 处办公位置）
因公司拥有两处不同的办公位置（对应 2 个不同的 Wi-Fi 网络），系统需同时允许这两个 Wi-Fi：
1. **获取 MAC 地址**：
   - 登录两个办公位置的无线路由器后台。
   - 分别记录这两个无线网络（SSID）对应的 **BSSID（无线网卡硬件 MAC 地址）**。
2. **录入企业微信**：
   - 登录企业微信管理后台（[work.weixin.qq.com](https://work.weixin.qq.com)）-> “应用管理” -> “打卡” -> “上下班打卡” -> “设置” -> “编辑/添加规则” -> “打卡 Wi-Fi”。
   - **点击“添加 Wi-Fi”，将这两个无线网络的 SSID 和 BSSID 均添加进白名单**。系统支持添加多组 WiFi，员工连接任意一组即可允许打卡。

### 4.2 步骤 2：安装并绑定 BLT1 蓝牙打卡器（3 个出入门通道）
公司办公室共有 3 个出入口通道，必须分别部署并绑定设备：
1. **物理安装**：
   - 分别将 3 台 BLT1 贴在大门 A、侧门 B、后门 C 的入口内侧墙面（建议高度 1.5 米，避开金属屏蔽）。
2. **多设备扫码绑定**：
   - 管理员在手机端打开企业微信 -> “工作台” -> “打卡” -> 右上角“设置” -> “设备管理” -> 点击“添加设备”。
   - 依次靠近 3 台设备进行蓝牙配对，分别命名为“大门打卡器-01”、“侧门打卡器-02”和“后门打卡器-03”。
3. **关联考勤组**：
   - 在考勤规则设置中，将这 3 台绑定的蓝牙设备全量关联至对应的打卡规则。**员工靠近 3 个门中的任意一个，手机即可感应蓝牙并完成打卡**。

### 4.3 步骤 3：设定打卡校验与对账规则 (三合一交叉验证逻辑)
系统将从企业微信 OpenAPI 同步回的手机 Wi-Fi 连接日志、大门蓝牙感应数据与实体门禁系统的刷卡时间戳导入本地数据库，执行三维交叉比对：
1. **尾随出门自动判定**：当员工的手机离线（Wi-Fi/蓝牙信号消失）但在对应时间段内**无任何出门刷卡记录**时，系统判定为“未刷卡尾随出门”并发出异常提醒。
2. **代刷卡自动判定**：当门禁系统在 18:00 记录了员工 A 的刷卡出门数据，但后台检测到 A 的手机在 16:30 就已断开公司 Wi-Fi 且无法感知蓝牙信号（时间差 > 15分钟），系统自动标记为“疑似代刷卡违纪”。
3. **感应时间窗口限制**：为了保障隐私和降低功耗，系统仅在以下**敏感时间窗口**内对手机的局域网/蓝牙连接状态进行扫描对账：
   - **早上上班窗口**：08:00 - 09:30
   - **午休就餐窗口**：11:30 - 13:30
   - **下午下班窗口**：17:30 - 19:00
   在上述窗口期之外，员工可自由关闭手机蓝牙和 Wi-Fi，系统不收集任何定位数据。

## 5. 考勤组与打卡方式隔离规则 (Office vs. Field Work)

为区分在办公室上班的内勤人员和外出的外勤/出差人员，在企业微信中通过**建立不同的考勤组**进行规则隔离：

### 5.1 办公室上班人员（内勤考勤组）
* **受众对象**：固定在两处办公位置上班的办公室日常职员。
* **打卡方式配置**：
  - 在考勤组中，将打卡方式**严格限定为“手机连接 Wi-Fi 打卡”或“考勤机打卡（关联3台蓝牙设备）”**。
  - **严禁勾选“允许外勤打卡（GPS定位打卡）”**。
* **效果**：内勤员工无法在办公室物理范围外进行任何打卡，彻底杜绝远程考勤作弊。

### 5.2 外出/出差人员（外勤与差旅组）
* **受众对象**：销售经理、软件工程师等频繁出差或跑现场的员工。
* **打卡方式配置**：
  - 勾选**“允许外勤打卡”**。
  - 并配置“外出/出差需关联审批单”。
* **外出 GPS 围栏考勤逻辑（技术完全可行）**：
  - **地图联想输入锁定**：外勤员工通过企业微信发起“外出/出差申请”时，输入目的地名称并通过**腾讯地图手动搜索定位组件**，精准锁定目的地的 GPS 经纬度（GCJ-02）。
  - **后置 GPS 比对（每日对账）**：员工在现场点击“外勤打卡”时，企业微信会获取其当前的 GPS 坐标。后端系统拉取打卡数据，并自动验证打卡 GPS 坐标是否在审批单锁定的目的地 **100米高精度地理围栏内**（或 500 米偏差审核缓冲区）。
  - **复合审计**：外勤人员除打卡外，必须每日在企业微信提交《现场工作日报》并上传包含现场工作环境的水印照片。

## 6. 方案可行性评估结论

经技术论证与企业微信平台配置核对，该方案在**技术上 100% 可行且支持在企业微信中直接配置**：
1. **多 Wi-Fi 支持**：企业微信打卡单组支持录入至少 20 个 Wi-Fi 节点（含 MAC 地址匹配），完全支持 2 处办公地点的 Wi-Fi。
2. **多蓝牙打卡机支持**：企业微信支持无限绑定官方蓝牙打卡硬件。单考勤组支持绑定多台考勤设备， 3 个门刷任意一个皆可识别。
3. **规则分组隔离**：企业微信“考勤组”功能成熟，完全能做到“内勤人员限 Wi-Fi 蓝牙打卡，外勤人员允许 GPS 围栏打卡”，实现规则的物理隔离。
