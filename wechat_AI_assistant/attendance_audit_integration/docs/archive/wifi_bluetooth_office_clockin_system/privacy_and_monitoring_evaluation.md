# 办公区 Wi-Fi、蓝牙与刷卡门禁三合一交叉审计技术方案及隐私合规评估

---

## 1. 方案设计思路：为什么“三合一”能解决代刷卡与尾随？

公司倾向于**不使用人脸识别**以降低员工对生物识别信息泄露的抵触，转而采用传统的 **IC/ID/NFC 刷卡门禁**。然而，刷卡门禁存在两个致命漏洞：
1. **代刷卡（代打卡）**：员工将卡片交给同事帮忙出门或下班刷卡。
2. **尾随出门（不刷卡）**：一人刷卡开门，多人跟着出入，导致门禁记录漏报。

为了在不用人脸识别的前提下解决上述问题，本方案设计了 **“Wi-Fi + 蓝牙 + 门禁刷卡”三合一交叉审计机制（Three-in-One Mutual Verification）**。员工可选择任意方式打卡，而系统后台通过三维数据流的“时间差对账”来自动捕捉代刷卡与尾随行为。

---

## 2. 三合一交叉审计算法逻辑

系统将员工的手机 Wi-Fi 连接状态、蓝牙信标（BLE）感应状态与物理门禁的刷卡时间戳进行三维勾稽。

```
     【员工状态监测源】
  ┌────────────────────────────────────────┐
  │ 1. 手机 Wi-Fi 状态 (BSSID 建立/断开)     │
  │ 2. 手机 蓝牙状态 (BLT1 广播侦测)       │ ───► 【考勤集成审计引擎】 ───► 【审计异常分类】
  │ 3. 物理门禁 刷卡记录 (时间戳)          │
  └────────────────────────────────────────┘
```

### 2.1 尾随出门（不刷卡）自动识别算法
* **场景**：员工 A 刷卡开门，员工 B 跟着 B 一起溜出去吃午饭，B 没有刷卡。
* **审计逻辑**：
  1. 系统检测到员工 B 的手机在 12:05 从公司 Wi-Fi 断开，且脱离了 3 个门口蓝牙打卡器的 BLE 广播范围。
  2. 系统检测到员工 B 的手机在 12:50 重新连接上 Wi-Fi，并再次侦测到蓝牙打卡器信号。
  3. 系统检索 12:00 - 13:00 之间的门禁刷卡日志，**发现员工 B 没有出门和进门的刷卡记录**。
  4. **判定结果**：标记为 **“未刷卡尾随出入异常”（Tailgating Anomaly）**。
  5. **提醒处理**：自动向员工 B 发送邮件警报，提示其：“系统检测到您已离开办公区，但门禁无刷卡记录，请务必遵守‘一人一刷’规则，以便系统正确对账。”

### 2.2 代刷卡（代打卡）自动识别算法
* **场景**：员工 A 下午 16:30 溜岗回家，将门禁卡交给员工 B，委托 B 在 18:00 下班时帮 A 在大门刷卡离岗。
* **审计逻辑**：
  1. 系统检测到员工 A 的手机在 16:32 从公司 Wi-Fi 断开，并且 3 个门口的蓝牙打卡器均无法再感知到 A 的手机信号。
  2. 到了 18:00，物理门禁系统上传了“员工 A 门禁卡刷卡出门”的记录。
  3. 系统比对 **【手机离线时间 (16:32)】** 与 **【门禁卡刷卡时间 (18:00)】**，发现两者时间差达到 88 分钟，远超系统设定的合理误差值（例如 10-15 分钟）。
  4. **判定结果**：标记为 **“疑似代刷卡/虚假在岗异常”（Buddy Punching Anomaly）**。
  5. **提醒处理**：触发高风险警告，抄送 HR 主管。

## 3. 时段限定蓝牙感应规则 (Time-Window Constrained Bluetooth)

为了最大程度保护员工隐私，消除员工对“全天候定位追踪”的顾虑，并降低手机耗电量与服务器压力，系统实施**时段限定感应规则**：

1. **非连续监听**：蓝牙打卡器与系统不进行全天 24 小时的后台持续监听，而是只在指定的**考勤敏感时间窗口（Active Windows）**内处于激活对账状态：
   - **早上上班窗口**：08:00 - 09:30（验证到岗）
   - **午休就餐窗口**：11:30 - 13:30（验证就餐离岗与返回）
   - **下午下班窗口**：17:30 - 19:00（验证离岗）
2. **员工自主权**：在上述窗口期外（如 10:00 - 11:30），员工可以自由关闭手机蓝牙和 Wi-Fi，系统不收集任何数据。系统仅在窗口期内对离线状态和刷卡进行勾稽。

## 4. 员工考勤与打卡交互体验 (三选一任选)

对员工而言，系统提供了极高的灵活性，员工在办公区只需满足**以下三种方式的任意一种**，系统即可通过后台交叉审核自动完成全天的打卡和在岗判定：

1. **方式一：Wi-Fi 打卡**（连接公司 Wi-Fi 即可自动打卡/登记在岗，无需手动操作）。
2. **方式二：蓝牙感应打卡**（手机开启蓝牙走过门口的 3 个蓝牙打卡器，自动感应登记）。
3. **方式三：门禁卡刷卡进出**（上下班、午休进出大门时，老老实实刷门禁卡，后台自动读取时间戳并补齐考勤）。

**技术优势**：
* 员工不用担心某一种方式失效。即使出门没带手机，只要刷了门禁卡，考勤依然有效；如果忘了带门禁卡跟人进来了，只要手机连上了 Wi-Fi 或被蓝牙感应到，系统便能识别其正常出勤并自动抵消“未刷卡异常”。

## 5. 中国法律合规保障 (不使用人脸识别的优势)

1. **完美规避生物识别信息合规红线**：
   - 刷脸打卡涉及收集员工的“面部特征信息”，这在我国《个人信息保护法》中属于极敏感的生物识别数据，受到网信办及法院的最严监管（如“人脸识别第一案”等司法判例）。
   - **采用 IC/NFC 刷卡 + 局域网 Wi-Fi + 蓝牙信号三合一对账，完全不收集任何生物特征数据**，在合规性上具有压倒性优势，能轻松通过外部审计与员工隐私合规评估。
2. **制度公示与员工手册民主程序**：
   - 尽管不收集人脸，但“门禁卡一人一刷、严禁代刷与尾随”的规定，必须明确写入《员工手册》并通过民主程序公示（由员工签字确认知悉）。
   - 处罚条款应规定：“若经系统交叉比对证实存在代刷卡行为，代刷人与被代刷人均视作严重违反劳动纪律”，以此确保在仲裁或诉讼中公司拥有坚实的制度支撑。

## 6. 员工知情权明确说明与合规公示文本模版 (Employee Disclosure & Consent)

根据《个人信息保护法》第十七条与第七条规定，公司在实施考勤对账信息流机制前，**必须向员工履行明确的告知义务，并取得员工的书面签字同意**。这不仅是法律的强制性要求，也是建立良好劳资信赖、避免管理冲突的必要手段。

### 6.1 告知与公示渠道建议
1. **书面或电子签署**：在系统上线前，要求每位员工亲笔签字签署《办公区考勤与数据处理知情同意书》。
2. **员工手册附件**：将该说明作为《员工手册》考勤管理章节的补充附件，进行民主公示。
3. **系统首次登录弹窗**：在员工首次通过手机查看个人考勤后台时，强制弹出《用户隐私协议与信息处理授权书》，勾选“我已阅读并同意”后方可进入。
