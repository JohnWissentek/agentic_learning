# MVP 开发全流程 Checklist（总路线图）

> 每个新项目从头到尾按这张表走。复制到新项目 `docs/CHECKLIST.md`，逐项打勾。
> 六个阶段：**定义 → 设计 → 开发 → 测试 → 验收 → 运维**。不允许跳阶段。
> 进度状态记录在 `docs/STATUS.md`（用 07 模板建立），本表是各阶段的出口条件明细；"下一个干什么"看 STATUS.md 第 0 节待办队列。
>
> **打勾权限标注**（每项开头标明谁打勾）：
> - **【AI】** = AI 完成该项工作后自行打勾；其中带 🤖 的项有机器闸门兜底（pytest/ruff/对账/hook 不过关，虚勾也提交不进去）
> - **【人】** = 由人签字担责的项。默认人亲自打勾；**人明确授权时（如"替我打勾"）AI 可代勾**——代勾前须向人复述该项内容并获确认，代勾后在 STATUS.md 开发日志登记"经人授权代勾"。责任始终归授权人；未经明确授权 AI 不得动【人】项
> - commit 不会自动打勾；打勾是显式动作。阶段门标 ✅ 的前提 = 该阶段所有项（含【人】项）全部勾完（`check_stage.py` 强制）

## 迭代规则（防跑偏三原则）

1. **任何改动先分级再动手**（00 总纲 2.3 变更分级协议 L1–L4）：AI 判定级别并报备入口层，人确认后从入口层向下游传播。新想法属 L1，先进 PRD 变更记录。
2. **禁止倒灌**：不允许代码先改、事后补图补文档。改动落地后对账必须通过（hook/pytest 自动强制）。
3. **每次迭代结束重跑本 Checklist 阶段四、五**，防止改 A 坏 B。
