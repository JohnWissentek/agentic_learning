# tools/check_stage.py 伪代码(信任链关键件)

## 本文件职责(一句话)
阶段门闸门:交叉核对 STATUS.md 阶段门表与 CHECKLIST.md 勾选状态,拦截"虚标阶段通过"和"跳阶段"。

## 对应PRD功能
00 总纲 2.4 闸门8("不许跳阶段"的机器化);06 Checklist 六阶段出口条件

## 依赖
- 调用:标准库(re, pathlib)
- 被调用:pre-commit hook、人工命令行

## 伪代码

函数 parse_checklist(CHECKLIST.md):
    按 "## 阶段一…六" 切分
    每个阶段: 统计未勾(⬜)与已勾(✅/☑/[x])条目数
    返回 {阶段序号: (未勾数, 未勾条目前3条)}

函数 parse_status_gates(STATUS.md):
    找到阶段门状态表
    每行提取: 阶段序号 + 状态(⬜未开始 / 🔵进行中 / ✅已通过)
    返回 [状态1..状态6]

函数 check():
    规则A(反虚标): 凡 STATUS 标 ✅ 的阶段, CHECKLIST 对应阶段不得有任何 ⬜
        违反 → 打印该阶段未勾条目, FAIL
    规则B(反跳阶段): 状态序列必须形如 ✅…✅ [🔵] ⬜…⬜
        出现 "非✅ 之后又有 ✅"(跳过前面阶段) → FAIL
        出现多个 🔵 或 🔵 在 ⬜ 之后 → FAIL
    两文件缺任一 → SKIP(项目初始化前)
    全部满足 → 通过,并打印"当前阶段 + 该阶段还剩 N 项未勾"作为进度提醒

## 异常与边界
- STATUS/CHECKLIST 尚未建立: 放行(闸门自身故障或文件缺失不锁死开发,与 check_process 同原则)
- 表格式被人为改坏(解析不到 6 个阶段): WARN 并放行,提示修表——宁可漏拦不误锁
- 勾选符号兼容: ✅ / ☑ / [x] 均算已勾;⬜ / [ ] 算未勾

## 注意事项 / 坑
- 本闸门只查"一致性",不查勾选的真实性:机器可验证项的真实性由其他闸门独立兜底
  (pytest/ruff/对账不过关本来就提交不进去),人工判断项(草图确认/浸泡)打勾=签字,责任在打勾者
- 打勾者=AI(完成工作时),确认者=人;commit 不自动打勾——打勾是签字行为,必须显式
