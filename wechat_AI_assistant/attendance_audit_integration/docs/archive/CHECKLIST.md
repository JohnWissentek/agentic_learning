# MVP 开发全流程 Checklist（总路线图）

> 每个新项目从头到尾按这张表走。复制到新项目 `docs/CHECKLIST.md`，逐项打勾。
> 五个阶段：**定义 → 设计 → 开发 → 测试 → 验收**。不允许跳阶段。

---

## 阶段一：需求定义（写代码前）

- ⬜ 用 PRD 模板建立 `docs/PRD.md`
- ⬜ 功能需求编号齐全（F1、F2…），每条有优先级
- ⬜ 用户故事覆盖所有主要操作路径
- ⬜ **"明确不做什么"已填写**
- ⬜ PRD 第6节边界/异常触发器清单逐条过完，形成 6.6 具体场景表
- ⬜ 外部依赖表填完（接口、凭证位置、降级策略）

## 阶段二：架构设计（写代码前）

- ⬜ 用架构模板建立 `docs/ARCHITECTURE.md`
- ⬜ 画出：上下文图、模块结构图、核心流程图（异常分支必须画）
- ⬜ 关键类/函数速查表初稿（先设计后编码）
- ⬜ 用 scaffold.py 生成标准项目骨架
- ⬜ 为计划中的每个代码文件建立伪代码文档（先写伪代码，再写代码）

## 阶段三：开发

- ⬜ 按伪代码实现，实现偏离伪代码时**先改伪代码**
- ⬜ 需求变化时**先更新 PRD 变更记录**，再动代码（防跑偏核心）
- ⬜ 每个模块完成即写单元测试（不留到最后）
- ⬜ 日志"必打点"六项覆盖（见 LOGGING_STANDARD 第3节）
- ⬜ 凭证全部在 .env，代码中无硬编码密钥
- ⬜ 每完成一个功能编号，回 PRD 第2节打勾

## 阶段四：测试

- ⬜ `pytest -m unit` 全绿，覆盖率达标
- ⬜ 第一次联调时抓取真实API返回，存入 tests/fixtures/
- ⬜ `pytest -m integration` 全绿（测试账号/测试库）
- ⬜ PRD 6.6 每条异常场景有测试且通过
- ⬜ 每个用户故事有 e2e 测试且通过
- ⬜ 故障演练：断网/错凭证/脏数据各来一次，日志能定位

## 阶段五：验收与交付

- ⬜ PRD 第8节验收 checklist 全部通过
- ⬜ ARCHITECTURE.md 图与最终代码一致（逐箭头核对）
- ⬜ 伪代码与最终代码一致（逐文件核对）
- ⬜ README.md：安装、配置(.env.example)、运行、常见问题四节齐全
- ⬜ 全新环境按 README 从零跑通一次（最真实的验收）
- ⬜ 部署方式落实（手动/定时任务/服务），运行凭证已配置
- ⬜ PRD 状态改为"已验收"

---

## 迭代规则（防跑偏三原则）

1. **任何新想法先进 PRD**：写入变更记录，评估影响范围，再改代码。
2. **文档与代码同步改**：PRD → 架构图 → 伪代码 → 代码 → 测试，链条上动一环，下游全部核对。
3. **每次迭代结束重跑本 Checklist 阶段四、五**，防止改 A 坏 B。
