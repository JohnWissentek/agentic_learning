# 企业微信审批模板调整与功能修订方案
## 目录: `attendance_audit_integration/feature_enhancements/wecom_template_adjustments.md`

---

## 1. 背景与目的
本考勤集成审计系统（Attendance & Leave Audit Integration System）采用严密的后置交叉比对与复合审计逻辑，对打卡、请假、差旅和加班工时进行合规校验。为了支撑系统后置审计的数据完整性，并防范虚假补卡和不合规的加班申请，必须对企业微信（WeCom）前端的审批模板进行配套的配置调整，确保前端录入的字段、控制项以及流程提示能够与后端审计要求完美契合。

为了配合未来的 GPS 围栏打卡，系统引进了基于**腾讯地图（Tencent Map）**的地址联想提示与定位组件。考虑到服务器负载及调用开销，地址录入采用**手动按钮触发模式（Button-Triggered Search）**。

## 2. 当前审批模板与审计需求差距分析 (Gap Analysis)

| 审批模板 | 当前企业微信配置 | 考勤集成审计系统需求 | 差距与问题 |
| :--- | :--- | :--- | :--- |
| **加班申请** | 仅有加班原因（文本）和时间区间。 | 1. 必须强制前置申请（严禁后补）。<br>2. 必须区分必要性原因。<br>3. 客户要求需附截图证明。<br>4. 自主加班需确认现场开工配合条件。 | 缺少前置控制、必要性下拉选择控件、证明图片上传控件和开工条件承诺复选框，缺乏合规警示。 |

| **外勤/外出申请** | 外出事由、时间区间。 | 外出目的地需进行地图搜索，确认并锁定精确 GPS 坐标以供围栏审计。 | 目的地输入框缺少手动地图搜索与经纬度锁定功能。 |
| **打卡补卡** | 补卡时间、补卡原因。 | 补卡仅用于漏打卡补登（非后补加班），需强制提供办公室现场水印照片。 | 缺少现场水印照上传控件，容易被滥用于规避正常出勤考核。 |
| **现场工作日报**<br>*(已有的日报模板)* | 现有常规工作日报表单。 | 出差人员每日必须提交日报，且强制上传包含现场环境的水印照片。 | 缺少强制性的“现场/办公室水印区域照片”上传校验，非必填。 |
| **现场服务报告** | 纸质服务报告上传。 | 必须包含客户现场代表手写签字的扫描件，且需附带现场水印照片。 | 缺少强校验与水印照片控件。 |

## 3. 具体模板调整方案

### 3.1 加班申请模板 (Overtime Request) - 模板 ID: `C4NvrtgmDKznbXFJCKEw5XGNyrw6dhLquQuNkq8Ze`
#### 调整方案：
1. **控制规则限制**：在企业微信审批后台设置加班“开始时间”必须大于或等于当前提交申请的时间（即**必须前置发起，系统自动拦截事后补交**）。
2. **新增控件列表**：

| 控件中文名 | 控件ID | 控件类型 | 必填性 | 配置详情 / 备选项 |
| :--- | :--- | :--- | :--- | :--- |
| **加班警示说明** | `ot-banner` | 说明文字 | -- | **红字显著提示**：“注意：加班必须在发生前发起前置申请，事后补交一律无效。加班工时确认采用后置复合审计（打卡一致性+工作日志+签字服务报告），审批通过不代表最终核算工时。普通周末加班可转为调休，法定节假日加班仅限发放法定加班工资，不累积调休假。” |
| **加班必要性类别** | `necessity-type` | 下拉单选 | **是** | 1. **客户紧急要求** (`customer`)：客户明确要求现场提供紧急服务或技术支持。<br>2. **项目进度关键节点** (`milestone`)：项目处于关键路径上，不加班将直接导致项目延期。<br>3. **突发故障/系统恢复** (`emergency`)：系统宕机、设备损坏等突发事故紧急抢修。<br>4. **自主工作安排** (`autonomous`) |
| **必要性证明材料** | `evidence-file` | 附件/图片 | 否 *(当必要性为“客户紧急要求”时为**强必填**)* | 上传能够证明客户要求的证据（微信群聊沟通截屏、客户邮件截图、现场项目经理统一签发的通知单等）。 |
| **现场开工配合确认** | `conditions-conf` | 单选/复选框 | **是** *(当必要性为“自主工作安排”时为**强必填**)* | 选项：“[ ] 我确认现场已具备工作配合条件（如有施工方、工程师配合，且设备可访问），不存在等待与闲置时间，且现场人员知情并配合。” |

### 3.2 出差申请与外出申请模板中的地址定位控件 (Address & Location Search)
#### 调整方案：
出差申请（`ZvVcpYA7cWdCjM3hr8aDhde5CXcYfGw2pVhiDP`）与外出申请中的“目的地”输入框，需改造为支持手动触发的腾讯地图定位组件。
1. **控件排版设计**：
   - 目的地输入框：单行文本输入框，ID 为 `dest-address-input`。
   - 地图检索按钮：位于输入框右侧的“**搜索定位**”图标按钮，ID 为 `dest-search-btn`。
2. **交互调用流程（手动触发限制）**：
   - 用户在 `dest-address-input` 中输入文本时，前端不执行任何 API 联想请求，杜绝打卡字即发送网络请求造成的服务器并发压力与接口流量浪费。
   - 当且仅当用户点击 `dest-search-btn` 时，前端向腾讯地图 WebService 接口 `apis.map.qq.com/ws/place/v1/suggestion` 发起单次请求。
   - 接口返回匹配结果后以悬浮弹窗形式向用户呈现，员工点击选择具体的正确位置（如特定的客户公司名、机场或火车站）。
   - 确认选择后，前端自动提取返回的 GCJ-02 经纬度坐标，写入不可见的隐藏控件 `dest-latitude` 和 `dest-longitude`，并作为最终审批表单的字段一并提交，供后端考勤定位引擎生成 100 米高精度电子围栏。
   - **防多连击机制**：对 `dest-search-btn` 实施 500 毫秒防抖与 1 秒内节流机制，防止因重复狂点按钮造成短时内大量重复调用 API。

## 4. 审批流程与抄送规则调整 (Workflow & CC Rules)

为了契合考勤提醒及项目经理的监管职责，企业微信审批流程后台需要进行如下调整：
1. **加班申请审批流**：
   - 员工发起 -> 关联项目的**项目经理 (PM)** 审批（检查必要性与现场开工条件） -> 部门主管审批 -> **HR 主管**（薛蕾/王晓）终审。
2. **打卡补卡审批流**：
   - 员工发起 -> 部门主管审批 -> **HR 主管**终审（强力核对照片水印与Wi-Fi登录历史，拥有最终一票否决权）。
3. **抄送（CC）机制配置**：
   - 所有加班、出差及补卡审批通过后，企业微信后台设置自动抄送（CC）通知给审计组：**王晓、薛蕾、徐宏玮、杨丽丽、孔紫初、王楠**，以保证数据同步透明。

## 5. 企业微信原生考勤打卡设置规范（限制现场相机拍照）

除了审批表单的配置外，管理员必须在企业微信的**考勤规则后台**开启强制性防作弊配置，锁定打卡照片的真实性来源：

### 5.1 上下班打卡强制拍照与相机限制
* **操作路径**：企业微信后台（[work.weixin.qq.com](https://work.weixin.qq.com)）-> 进入“应用管理” -> “打卡” -> “上下班打卡” -> “设置” -> “编辑/添加规则” -> “打卡方式” -> “更多设置”。
* **配置项 1：开启拍照打卡**：
  - 勾选 **“打卡必须拍照”**（打卡时自动调用相机拍照，不满足拍照的打卡无效）。
* **配置项 2：锁定仅限现场拍照（最核心安全控制）**：
  - 勾选 **“仅限现场拍照（限制从相册选择照片）”**。
  - 启用此配置后，员工在打卡时，企业微信客户端会自动屏蔽“从相册选择”或“多开虚拟摄像头”的文件选取入口，强行调起手机原生相机的实时对焦快门，从源头上杜绝了使用旧照片、代自拍或预存背景图打卡的漏洞。

### 5.2 外勤/外出打卡强制拍照与相机限制
* **操作路径**：企业微信后台 -> “应用管理” -> “打卡” -> “上下班打卡” -> “设置” -> “编辑/添加规则” -> “允许外勤打卡” -> “更多设置”。
* **配置项**：
  - 勾选 **“外勤打卡必须拍照”** 并勾选 **“仅限现场拍照”**。
  - **效果**：外勤人员以及第一阶段出差人员在使用企业微信进行手动外勤打卡时，必须实时自拍，且无法使用相册图片。
