## 1. 背景与目标

- **要解决什么问题**：企微打卡、审批、后置凭证与花名册分散，人工勾稽成本高、调休难算、缺审计痕迹。
- **目标用户**：员工、部门主管、HR、高管（邮件抄送与封账操作为主）；调休催用仅项目管理白名单（孔紫初、王楠）。
- **成功标准（一期）**：
  - 日审按**动态工时公式**（上班打卡 + 8.5h/9.0h，8:30–18:30/19:00 截断）与假勤审批勾稽 T-1，并邮件告警；
  - 月审按薪资周期产出草稿/终审报表；
  - 合格加班可入调休流水，无签字服务报告不入账；
  - 出差月的差旅补助减半规则（现场不足 4h）可与金蝶报销单交叉核对并输出差异「待核」清单（F15）；
  - 调休逾期催用只通知孔紫初、王楠；
  - 人工改账必留 `audit_logs`；封账后不可静默重算。
- **明确不做什么（Out of Scope）**：
  - **二期硬件与交叉审计**：不部署 BLT1 蓝牙打卡器、联网门禁及 Wi-Fi/蓝牙/门禁三合一交叉审计（见 §1.2）
  - **二期业务启用**：不实施外勤 GPS **围栏强校验**接入日审（F13）；不因二期方案改班次/打卡方式
  - **不自建**人脸/生物识别库或人脸特征存储；一期只消费企微现网已配置的打卡结果（现网可含人脸+定位，由企微侧完成）
  - 不调用法定节假日外部 API（全年手动维护）
  - 不自动执行旷工扣薪/辞退处分——惩戒须 HR 人工流转（制度民主程序见合规附录）
  - 不做完整 HR Web 门户看板（MVP 以 CLI/API + 邮件为主）
  - 不改造企微审批表单本体（只拉取现有数据）
  - 已封账月份不自动重算（须 HR 正式追溯调整）

## 3. 用户故事

### US-1：员工收到日异常并核销
作为【员工】，我要在工时缺额次日收到邮件（写明打卡时刻、应出勤 8.5h/9.0h、缺额小时与核销路径），并在当天或当月内通过企微申请调休/年假冲抵，以便避免按无酬缺勤扣减。坐班遗忘打卡不再有常规补卡通道；硬件/网络故障走故障核销。

### US-2：主管审阅团队异常
作为【部门主管】，我要收到部门异常抄送，以便督促核销与审批假单/故障核销申请。

### US-6：财务核对差旅补助（F15）
作为【财务】，我要在月审时收到「金蝶报销单补助金额 vs 企微现场工时判定」的差异待核清单，以便在金蝶复核阶段人工修正减半/全额核发错误。

### US-3：HR 月审封账
作为【HR】，我要在 25/26 日拿到周期报表并封账，以便输出可追溯的扣薪与调休数据。

### US-4：项目侧掌握调休积压
作为【项目经理（孔紫初/王楠）】，我要在调休逾期未用时收到催用邮件（不含员工本人），以便安排项目资源与督促调休。

### US-5：高管只读合规趋势
作为【高管】，我要收到日/周/月关键异常抄送，以便掌握合规与成本风险。

> 本 MVP 无独立 Web UI；界面以邮件模板（`preview/`）与 CLI 为准，不强制 Excalidraw 草图。

## 4. 关键业务规则

> 决策树可视化见 `docs/ARCHITECTURE.md` **§4**（Mermaid 节点须含具体数值）。改规则须同步改下表与图。  
> **v0.5 起**：全部口径以 **2026-08-21 民主确认版制度**为准；条款号形如「制度 3.1.1」均指该版《考勤管理制度》。ARCHITECTURE §4 若仍写固定 09:00–17:30 / 打卡窗 / 16h 上限，视为待同步的设计债（下一 L2）。

### 4.1 规则参数表（硬数字，人审重点）

| 参数 | 取值 | 说明 |
|---|---|---|
| 日审触发 | 每天 **09:00** | 审计对象为昨日 **T-1** 全天（作业时刻，非工时规则） |
| 周审触发 | 每周一 **10:00** | 范围：上周一～上周日 |
| 月审草稿 | 每月 **25** 日 | `cli monthly` |
| 月审终审 | 每月 **26** 日 | `cli monthly --final`，成功后封账 |
| 薪资周期 | **上月26日～本月25日** | 非自然月；**待 HR 书面固化**（制度未规定周期，见终审 F-08） |

### 4.2 规则条文

1. **日审（一期，制度 3.1.1/3.1.2/3.2）**：
   - **截断**：上班打卡早于 08:30 的起算时刻取 08:30；无加班单时下班晚于 18:30 截到 18:30（9.0h 顺延日截到 19:00）。
   - **判定**：`NORMAL` = 区间内成对打卡且截断后跨度 ≥ 当日应出勤（默认 8.5h；午休满 1h 为 9.0h）。引擎**按公式判定，禁止写死 10:00**（请假顺延 10:00+N、9.0h 顺延日会算错）。
   - **缺额分级**：实际工作时长（跨度减午休）满 4h 不足 8h，或跨度不足应出勤 → `PENDING_RECONCILIATION`，勾稽已批假单/核销单后仍缺的进提醒邮件；实际工作 <4h 且无审批 → `ABSENT` 旷工预警（不由系统定性处分）。
   - **0 条打卡** → 全日缺勤预警；**1 条打卡** → 跨度无法计算，标待核推人工（**不再自动折 0.5 天**，旧口径作废）。
   - 请假期间打卡标「在假但打卡」；无审批外出/外勤标异常。缺额由员工当天或当月内自主冲抵，被动抵扣月累计 4h 封顶，超出部分按无酬缺勤公式导出供 HR。
2. **薪资周期**：上月 26 日–本月 25 日；25 日初步月报，26 日终审（含服务报告/日报复合校验）。
3. **法定加班**：仅记加班工资工时，**禁止转入调休**。
4. **非法定加班调休**：须有前置加班审批 + **加班打卡** +（安装调试等场景）**客户/用户手写签字服务报告**，否则不生成调休；出差非工作任务时间不计加班。
5. **花名册**：本地 JSON（`data/employee_roster.json`）维护姓名与邮箱；**禁止运行时读 xlsx**。
6. **邮件收件规则**：
   - 日/周/月异常：抄送 王晓、薛蕾、徐宏玮、杨丽丽（及员工本人按现有模板）；
   - **调休催用（F11）**：**TO** 孔紫初、王楠；**CC** 徐宏玮、薛蕾；**禁止**发给或抄送被催员工。
7. **封账**：终审成功写入锁；同周期禁止静默重算。
8. **外勤 GPS 围栏（F13，二期）**：启用后与审批锁定目的地距离 **≤200 米有效；>200 米无效**。一期可保留坐标数据拉取，但**不得**据此自动判无效。
9. **出差考勤节点（制度 4.2）**：日开始 = 到达出发地长途交通站点或客户办公/工作区域（多点取首个）；日结束 = 离开站点或客户现场（多点取末个）。里程碑打卡（站点/现场到离，含夜间）为制度义务；须事前出差审批；每日提交现场工作报告。
10. **调休使用建议**：建议当年内用完；特殊原因经主管审批可延至**次年头两个月**。
11. **在途调休（制度 4.3，接入 F10）**：周末/休息日在途按票据时刻 + 前后各 1h 通勤核定单程时长：≤2h 不计；>2h 且 ≤4h 计 0.5 天；>4h 计 1 天。充值须主管/HR 核准，系统不自动充扣。
12. **金蝶差旅报销交叉审计（F15，一期只做补助减半核对）**：
    - **数据源**：复用 `kingdee_client`（`LoginByAppSecret` 登录 + `ExecuteBillQuery` 查询差旅报销单/费用报销单），**只读**；凭证放 `.env`（`KINGDEE_*`）。
    - **勾稽规则（制度 4.2.3）**：按出差日逐日核对——企微打卡/日报判定的「单日现场技术工作时长」<4h 时，金蝶报销单该日差旅补助与餐补应减半；若「现场 + 当日在途」合计 ≥4h 且未办理请假折抵，应全额；主观滞留日不应核发。金额不符 → 输出「补助待核」差异行（员工、日期、判定工时、应发口径、金蝶实发）。
    - **边界**：客观等待待命经主管书面确认（工作留痕）的全额核发——引擎无法读确认单时只标待核，不判错。
    - **禁止**：不回写金蝶、不自动扣发、不修改报销单状态；差异仅推财务与 HR 人工复核。
    - **失败策略**：金蝶 API 失败重试 + 退避；连续失败**跳过本轮交叉审计并告警管理员，不阻塞考勤日审/月审主流程**。
