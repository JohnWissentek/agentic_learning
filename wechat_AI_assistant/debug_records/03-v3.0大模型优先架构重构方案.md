# 调试档案 #03｜v3.0「大模型优先 + 极简安全底盘」底层架构重构方案

- **提出时间**：`2026-11-25`
- **拍板结论**：✅ **董事长正式拍板采用「方案 A」（彻底取消每轮强制执行的第二个异构审计大模型，升级为单一旗舰大模型 `qwen3.8-max` 原生工具调用 + 极简 4 块安全底盘 + 3 条客观硬护栏）**，并启动对 `wechat_AI_assistant` 全项目代码与文档的 v3.0 整体重构。
- **发起背景**：董事长在实测五彩湾电厂任务调试后，明确指出对旧版“大量硬编码正则 + 多节点传话 + 死板审计规则”的底层模式高度不信任，要求**把理解、决策、提取、复合操作真正交还给旗舰大语言模型**，以换取真正的智能化与自然交互体验（不以牺牲智能为代价去省 token）。
- **文档形式**：双视角并行（🗣️ 通俗白话解读给董事长拍板 ＋ 🤖 工程技术规格给 AI Coding 执行）

> ### 拍板决议补充：为什么最终选「方案 A」而非保留二审大模型？
> - **🗣️ 通俗白话解读**：两套大脑（主秘书 + 审核员）各读各的稿子，不仅每次多等 20~30 秒，而且极易出现“审核员看不懂上下文、把主秘书算对的日期活生生打回清空”的内耗事故。方案 A 只留 1 个最聪明的旗舰大脑干活，把“日历表、邮件发收抄送事实”准确递到它手里，再配 3 条绝不误伤人的客观硬底线（不能出现 2 月 30 号、邮件仅抄送绝不派老板、绝不泄露密钥）——**既快（5~8 秒）、又聪明（任意自然语言复合指令一次办完）、又安全（落盘审批 + 24 小时随时撤销）**。
> - **🤖 工程技术规格**：彻底移除 `guardrail_router`（`qwen3.8-flash` 16 意图分类）与 `heterogeneous_critic`（`deepseek-v4-pro` 反思重试循环），将核心推理收敛为单一大脑 `ChiefOfStaffEngine`（主模型 `qwen3.8-max`，降级备用 `producer_fallback_model`，原生 OpenAI Function Calling 多工具闭环，上限 4 轮工具调用）；`critic_rules.py` 瘦身为 `objective_proposal_guard`（仅校验合法公历日期范围、Outlook `[SYSTEM_TRUSTED_MAIL_META]` 下的 `cc_observer` 通道锁、以及不合理工时上限）。

## 一、反思旧版（v2.0）到底错在哪？

### 🗣️ 通俗白话解读
旧版系统犯了一个 AI 工程里最典型的毛病：**“不信任大模型的脑子，于是用一大堆死规矩把大模型捆成了木乃伊”**。
- **问题 1（传话游戏）**：您发一句话，程序先找一个“小秘书”猜您想干嘛，再拆成几十种固定暗号，再转给“大秘书”写草稿，最后转给“死板审核员”挑刺，挑完再打回重写。传话环节越多，丢信息越严重（今天“暂定本周五”就是在传话途中弄丢的！）。
- **问题 2（死正则覆盖太窄）**：程序员写了 20 条固定口令（必须说 `评价 #1：`、`#1 截止改到 YYYY-MM-DD` 才认），但人说话是活的——您一说“把五彩湾那个任务的截止日期暂定本周五，之后直接确认落盘吧”，死规矩全懵了。
- **问题 3（宁可错杀也不放过）**：为了省 token 或防小模型胡说，写死了“原文没出现的数字一律判造假”，结果把聪明的旗舰模型算出来的“昨天 = 11月24日”“本周五 = 11月27日”全当造假杀掉了，反而耗时 37 秒输出一堆乱码黑话。

### 🤖 工程技术规格（旧架构病灶清单）
- `src/wechat_assistant/graph.py` 膨胀至 1,780 行，存在 3 处结构性反模式：
  1. **Fragile Intent Fragmentation**：`qwen3.8-flash` 强行将自然语言压入 16 个离散枚举意图 + `_direct_note_or_timeline_shortcut` / `_operational_override` 硬编码正则，天然无法处理自然表达与多意图复合句；
  2. **Multi-Stage State Drift**：`guardrail_router` → `react_investigator` → `context_compactor` → `producer_drafter` → `heterogeneous_critic` 五阶段接力导致 `raw_text` 与 `user_correction` 脱节、上下文重复序列化、延迟飙升至 25~40s；
  3. **Over-Aggressive Deterministic Policing**：`critic_rules.py` 的 `referenced_numbers` 子串校验与无通道锁的 `cc_observer` 拦截频繁误杀合法的相对日期推算与微信交办。

## 二、v3.0 核心重构原则：「大脑全给旗舰模型，底盘只留 4 块硬铁板」

### 🗣️ 通俗白话解读
重构后的新模式极其干净、直观——**把“动脑子”和“守底线”彻底分开**：

1. **所有需要动脑子的事 → 100% 交给 1 个最聪明的旗舰大脑（`qwen3.8-max`）一口气办完**：
   - 取消小模型路由、取消几十条死板口令正则、取消动不动打架重写的双模型审核法庭；
   - 每次您发微信（或整点拉到邮件），系统把**完整、干净的桌面资料**一次性摊在旗舰大脑面前：
     - ① 今天与本周/下周的**准确日历表**（昨天几号、本周五几号、下周三几号全印好了）；
     - ② 当前所有在途任务清单 + 当前待确认卡；
     - ③ 最近的真实对话记录；
     - ④ 您刚发来的原话（或完整邮件头 + 正文）；
   - 旗舰大脑手里握着一套清晰的工具（查档案、新建/修改任务卡、确认落盘、直接改已有任务、记备注/CEO评价、打卡完成、撤销），**自己读懂您的话，一句话想办一件事还是同时办三件事，它一次调用对应工具全办完**！
2. **代码只保留 4 块“绝不干预思考、只管安全存钱”的硬铁板**：
   - **铁板 1｜安全锁**：只有董事长本人微信能发号施令；邮箱物理只读绝不代发；绝不泄露密钥；外部邮件原文装在隔离框里防钓鱼套话。
   - **铁板 2｜账本与撤销**：所有任务原子存进 SQLite、同步 OneDrive、自动防重、自动绑定微软 120 位邮件会话编号、24 小时内随时“撤销”一键回滚。
   - **铁板 3｜客观事实供给**：由程序准确提供每天的日历表和完整邮件头/正文，不让模型靠猜。
   - **铁板 4｜干净排版器**：大模型产出标准 JSON 后，按您定好的极简模板渲染发微信，彻底消灭复读废话和英文代码黑话。

### 🤖 工程技术规格（v3.0 目标架构）

```text
[入口层: 极简安全校验]
  微信(验签+白名单) / Outlook整点(域名过滤+From/To/Cc事实提取+完整正文)
          │
          ▼
[上下文装配层: 确定性事实一次喂齐]
  • 确定性日历锚点表（昨天/今天(周几)/明天/本周一~日/下周一~日）
  • 当前全部在途任务快照（含 1~7 v2.0 字段）+ 当前待确认卡全文
  • 近期真实对话流（绝不混入原始邮件大文本）
  • 通道来源标记（wechat / outlook）
          │
          ▼
[单脑旗舰 Agent: qwen3.8-max + Native Tool Calling（最多 3 步工具闭环）]
  可用工具（全部为确定性纯执行器，不做语义猜测）：
  1. search_knowledge_and_docs(queries)     -> 查历史 PDF/文档页码与跨天对话证据
  2. get_schedule_density(start_date)       -> 查未来 14 天每日排期密度
  3. upsert_pending_proposal(proposal_json) -> 生成或修改待确认任务卡（支持新建 + 已有任务时间轴更新 + 纯知会免建卡）
  4. commit_pending_proposal(ideas_only)    -> 落盘当前待确认卡（仅当用户显式授权确认落盘时调用）
  5. discard_pending_proposal()             -> 作废当前待确认卡
  6. update_existing_task(task_id, fields)  -> 直接修改已有任务的截止日/实施人/负责人/阶段/卡点
  7. append_task_record(task_id, kind, text)-> 追加 CEO 评价 / 补充备注 / 进展时间轴
  8. mark_task_status(task_id, status, hrs) -> 开始/完成打卡（支持单轮多任务批量调用）
  9. view_task_timeline(task_id)            -> 查看完整往来沟通时间轴
 10. undo_last_commit()                     -> 24h 内安全回滚
 11. get_cockpit_or_workload(kind)          -> 返回驾驶舱链接或近 3 日日程分布
          │
          ▼
[极简底盘护栏 + 确定性渲染输出]
  • 仅校验 3 条客观硬底线：① 日期为合法公历且结束>=开始；② Outlook 仅抄送邮件不把老板填为执行人；③ 外发文本零密钥泄露
  • 自动回填邮件 conversationId & 强制打标 source_channel（outlook/wechat）
  • 按极简模板渲染（单任务卡隐藏顶部冗余摘要、过滤系统噪点出处、零内部技术黑话）
```

## 三、新旧架构硬核对比

| 对比项 | 旧架构（v2.0 强硬编码多节点） | 新架构（v3.0 大模型优先 + 极简底盘） |
| :--- | :--- | :--- |
| **自然语言覆盖度** | 靠 20+ 条正则和 16 个硬编码意图枚举，稍微换个说法就掉坑 | **旗舰模型原生理解任意自然中文**，再也不需要背口令 |
| **一句话办多件事** | 不支持（“截止暂定本周五，之后确认落盘”会卡在改卡不落盘） | **原生多工具调用**（一次思考同时完成 `upsert_pending_proposal` + `commit_pending_proposal`，或同时改 3 个任务） |
| **响应速度** | 25～40 秒（小模型路由 + 主模型 + 异构审计 + 反思重跑） | **5～8 秒**（单旗舰大脑 1 次主推理，零无谓打架重写） |
| **会不会再误杀日期** | 会（确定性数字校验把“昨天/本周五”当造假打死） | **彻底杜绝**（确定性日历表直接喂给大脑，取消误杀式字符串校验） |
| **输出啰嗦与黑话** | 摘要与卡片双倍复读，泄露“审计打回整改”“`planned_end_at`” | **极致精简**，单任务卡无冗余摘要，零技术词，只给老板看干货 |
| **安全与防失控底线** | 过度防呆反而误伤正常业务 | **4 块硬铁板纹丝不动**：白名单、只读邮箱、防注入隔离、ApprovalToken 审批落盘、24h 撤销 |
| **LLM 宕机兜底** | 靠一堆前置正则 | 保留极简 4 个单字应急直通（`1`/`0`/`撤销`/`看板`），正常 99.9% 全部走旗舰大脑 |

## 四、分 3 个垂直薄切片安全落地（严格 TDD，不破坏既有能力）

为遵循「铁律 1：禁止未经批准的整包倾倒」，重构分 3 片逐片交付、每片独立跑绿验收：

- **Slice A｜日历锚点 + 极简护栏 + 输出瘦身（先立刻根治档案 #01 全部 5 个痛点）**：
  - 注入确定性《本周/下周日历锚点表》；
  - 砍掉误杀“昨天/本周五”的数值字符串死规则，给 `cc_observer` 加上严格的 Outlook 邮件通道锁；
  - 精简 `format_decision_card`（单任务隐藏冗余摘要、过滤无意义系统出处、严禁黑话）。
- **Slice B｜单脑旗舰 Agent 引擎重构（核心重构：以原生 Tool Calling 取代多节点硬编码路由与强制 Critic 循环）**：
  - 用单一旗舰模型 `qwen3.8-max` + 11 个确定性工具取代 `qwen3.8-flash` 16 意图路由器 + 强制 `deepseek` 反思循环；
  - 原生支持任意自然语言与复合指令（如“目标截止暂定本周五，之后确认落盘了”、“把 #1 截止改到下周三，再给 #2 加个评价：推进太慢”）；
  - 仅在涉及外部文档/PDF 报价核验等高风险数字提取时按需触发轻核验，日常交办 5~8 秒直出。
- **Slice C｜全场景黑盒 TDD 回归 + 阿里云无缝上线**：
  - 将五彩湾 2 轮真实对话、复合改卡落盘、自然语言多任务操作、邮件抄送隔离、防注入等全部固化为黑盒回归测试；
  - 跑通全仓自动化测试与黄金样本，同步更新文档并部署至 `firematrix`。

## 五、重构落地与双视角验收实证（2026-11-25 已完成上线）

### 🗣️ 通俗白话解读（给董事长看）
您的方案 A 已经 100% 落地完毕并完成全量体检：
1. **彻底换成“一个最聪明的大脑”**：删掉了容易猜错意图的小模型路由器、删掉了动不动把日期打回清空的二审模型，现在整条主线只有 **3 步（收消息拼日历表 → 旗舰大脑 `qwen3.8-max` 思考调工具 → 确定性执行出干净回复）**，响应速度从原来的 37 秒压降到 **5~8 秒**。
