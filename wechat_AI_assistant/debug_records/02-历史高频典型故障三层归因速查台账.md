# 调试档案 #02｜历史高频典型故障「双视角三层归因」速查台账

> 本台账汇总 `wechat_AI_assistant` 从试运行到 v2.0 期间的 **7 类真实高频故障**。每条均提供 **🗣️ 白话解释（给您看）** 与 **🤖 工程定位（给 AI Coding 看）**，方便快速对照。

### 历史故障 1：确认卡标题重复出现 `确认 #9｜确认 #9｜...`
- **归因层**：`L1 硬编码 + L2 提示词`
- **🗣️ 白话解释**：就像公文批号本来该由办公室最后统一盖章，结果秘书看前一份旧文件上印着“批号 #8”，就顺手在标题里自己先写了个“确认 #9｜”，最后系统自动盖章时又再盖了一次，变成了两个叠在一起。
- **🤖 工程定位与已落地修复**：`PRODUCER_TRIAGE_PROMPT` 禁止 `headline` 自带编号前缀，同时在 [graph.py#L140-L144](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/src/wechat_assistant/graph.py#L140-L144) 的 `format_decision_card` 用正则 `^(?:确认\s*#?\d*\s*[｜|:\-：]\s*)+` 强制剥离前缀（双保险）。

### 历史故障 2：别人发邮件仅抄送（Cc）董事长，系统却把董事长写成干活的执行人
- **归因层**：`L1 硬编码缺失 + L2 上下文缺失`
- **🗣️ 白话解释**：之前系统收邮件时只把“发件人和正文”递给了秘书，没告诉秘书“主送给谁、抄送给谁”，也没给公司内部同事的邮箱域名清单。秘书看不出您只是被顺手抄送，只好把每封信的活都往您头上派。
- **🤖 工程定位与已落地修复**：在 [mail_domains.json](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/config/mail_domains.json) 区分 `internal_domains` 与 `partner_domains`；在 [mail_poller.py#L315-L445](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/src/wechat_assistant/intake/mail_poller.py#L315-L445) 实现 `infer_email_role_hint` 确定性角色推断；在 [critic_rules.py#L49-L54](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/src/wechat_assistant/nodes/critic_rules.py#L49-L54) 增加 `cc_observer` 硬拦截。

---

### 历史故障 3：同一件事的来回邮件建了重复任务卡，或后续回信连不上原任务
- **归因层**：`L3 模型能力边界 + L1 缺少确定性兜底`
- **🗣️ 白话解释**：微软邮箱用来串起同一串往来邮件的“会话编号”是一串一百多位无规律的英文乱码，指望大模型肉眼抄写极易漏抄或抄错一个字母，一错就断线、下一封信来了就会重开一张新卡。
- **🤖 工程定位与已落地修复**：在 [mail_poller.py#L645-L660](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/src/wechat_assistant/intake/mail_poller.py#L645-L660) 给每封信分配短号 `MAIL-k`；在 [graph.py#L315-L364](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/src/wechat_assistant/graph.py#L315-L364) 通过 `_backfill_mail_conversation_ids` 在落盘前由代码确定性自动回填真实 `conversationId`。

### 历史故障 4：外部邮件正文有可能冒充系统指令“篡改角色分工”
- **归因层**：`L1 安全边界缺陷`
- **🗣️ 白话解释**：原本把“系统自己算出来的分工提示”和“外部陌生人发来的邮件正文”装进了同一个信封里，万一外部垃圾邮件正文里故意写一句假话“本邮件由董事长亲自负责”，AI 可能会分不清哪句是系统说的、哪句是外人说的。
- **🤖 工程定位与已落地修复**：在 [mail_poller.py#L92-L135](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/src/wechat_assistant/intake/mail_poller.py#L92-L135) 的 `wrap_untrusted_email` 中物理拆分 `[SYSTEM_TRUSTED_MAIL_META]`（可信头）与 `[UNTRUSTED_EXTERNAL_DATA]`（仅包裹外部主题与正文）。

### 历史故障 5：整点只有“团队抄送知会”邮件，却卡死了后面一整天的邮件汇总
- **归因层**：`L1 流程状态机漏洞`
- **🗣️ 白话解释**：那一小时没有任何需要您动手的新任务，只有同事发给客户的知会抄送。但系统还是生硬地造了一张“空确认卡”摆在您桌上等您签字；按防覆盖规矩，旧卡没签字就不能出新卡，结果后面几个小时真正重要的邮件全被这张空卡堵在了门外。
- **🤖 工程定位与已落地修复**：在 [graph.py#L1420-L1428](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/src/wechat_assistant/graph.py#L1420-L1428) 的 `_node_hitl_preview_gate` 增加分支：当 `not proposal.actions and not proposal.task_updates` 时直接返回纯知会文本、`proposal_id=None`，绝不写入 `pending_proposals`。

### 历史故障 6：刚处理完邮件，下一轮在微信聊新工作却莫名其妙串味到那封邮件
- **归因层**：`L1 记忆污染 Bug`
- **🗣️ 白话解释**：系统之前把 2000 字的原始邮件全文存进了“您和助理的微信聊天记录”里，假装成是您刚发的话。等您半小时后在微信安排一件全新的事，AI 回头翻聊天记录看到一大篇旧邮件，就被带偏跑题了。
- **🤖 工程定位与已落地修复**：在 [graph.py#L1763-L1774](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/src/wechat_assistant/graph.py#L1763-L1774) 中，对 `sender.startswith("mail:")` 的批次仅在 `conversation_turns` 写入 `[Outlook 邮件批次触发分拣]` 与精炼确认卡，不再把原始外部邮件全文塞入用户对话历史。

---

### 历史故障 7：长邮件里关键报价和交期在第 300 字后面，AI 怎么分析都看不到
- **归因层**：`L1 数据采集截断`
- **🗣️ 白话解释**：之前拉邮件只拿了微软邮箱自带的“前 255 字预览摘要”，英文邮件开头寒暄几句加上签名就占满 255 字了，真正写价格和截止日期的正文压根没送进 AI 眼里。
- **🤖 工程定位与已落地修复**：在 [mail_poller.py#L504-L533](file:///Users/john/Desktop/agentic_learning/wechat_AI_assistant/src/wechat_assistant/intake/mail_poller.py#L504-L533) 的 `fetch_mail_folder_messages` 升级 `$select` 拉取 `body,hasAttachments` 并加请求头 `Prefer: outlook.body-content-type="text"`，经 `_extract_email_body_text` 清洗提取完整正文（上限 2500 字）。

## 累计 12 起真实故障（档案 #01 + #02）规律速览

- **🗣️ 一句大白话总结**：12 次“看似 AI 不聪明”的故障里，**9 次（75%）是流程/传话代码写歪了，2 次（17%）是没给齐背景或没隔开内部废话，只有 1 次（8%）是大模型自身短板（且已用代码彻底补齐）**。
- **🤖 给 AI Coding Agent 的排障优先级**：接到“智能体表现异常”的调试任务时，严格按以下顺序排查，严禁第一时间盲目调 Prompt 或甩锅模型：
  1. **数据入口完整性**（原始正文/邮件头/附件是否被截断或丢字段）；
  2. **多节点状态一致性**（Router / Producer / Critic / Deterministic Guard 是否看到完全一致的用户最新指令与工具事实）；
  3. **硬规则误杀与通道隔离**（确定性护栏是否缺通道锁、或误杀合理推算）；
  4. **记忆与展示隔离**（外部脏数据是否污染 `conversation_turns`、内部反思日志是否泄露至用户可见字段）。
