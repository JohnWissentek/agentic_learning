# 早间工作报告标准模板与独立任务卡管理规范（v2.0 扁平单层版）

> **核心理念**：**「一件事 = 一张独立任务卡，办完即闭环」**。  
> 彻底取消“大项目里套无数子任务”的复杂双层嵌套——董事长只追着一件件独立具体的事办；同一大方向/大客户的多张任务卡仅用轻量级「归属项目」标签关联（用于筛选检索与 OneDrive 同目录归档），互不嵌套、零复读、干净利落。  
> **配套规范（同一份标准 JSON 驱动所有通道）**：
> - 底层唯一标准 JSON 契约：[task_card_schema.json](task_card_schema.json)（大模型分析、数据库、早报、邮件汇总、驾驶舱共用同一套结构）
> - 邮件按小时汇总与 `From/To/Cc` 角色推断规范：[邮件汇总模板.md](邮件汇总模板.md)

## 一、《早间工作报告》标准输出模板

> **展示原则**：每件在途独立任务为一张标准卡片，固定包含 **1）～5）核心管理要素 + 6）补充备注（Comments）+ 7）CEO 评价**；无内容的 `6）`、`7）` 自动隐藏，绝不刷屏、绝不复读。

```text
🌅 早间工作报告（YYYY-MM-DD）
📊 在途任务：M 项 ｜ 外部等待：K 项 ｜ 临期/超期预警：X 项

━━━━━━━━━━━━━━━━━━━━
【任务 #ID】<任务名称>（归属：<项目/板块>｜<P0/P1/P2>｜<待办/进行中/等待外部>）
1）目标与交付成果：<办完必须产出的可验收硬结果：文档/图纸/BOM/签字协议/样机实物/测试通过；含验收标准>
2）当前进度与往来沟通：<当前所处阶段>；最新进展/往来（默认展示最近 2～3 条，全量可查）：
   - [MM-DD HH:MM｜微信/邮件｜谁→谁] <一句话进展或沟通事实>
3）责任分工：负责人：<总负责/拍板人> ｜ 实施人：<内部执行人> ｜ 外部协作：<客户/设计院/供应商对接人，无则填无>
4）时间排期：开始 <YYYY-MM-DD> → 目标截止 <YYYY-MM-DD 或 【待补齐】>（已进行 X 天｜距截止剩 Y 天 / 超期 Z 天）
5）卡点与关联档案：<当前等谁/卡在何处/已等天数/风险提醒，无则填无> ｜ 档案：<关联图纸/文档/邮件名>
6）补充备注（Comments）：<超出 1～5 条的所有客观细节、技术约束、背景说明，无则不显示>
7）CEO 评价：<董事长针对本任务的评价、态度、催办批示或复盘判断，无则不显示>

━━━━━━━━━━━━━━━━━━━━
👉 微信直接回复：`完成 #1` 闭环 ｜ `评价 #2：...` 加 CEO 评价 ｜ `备注 #2：...` 加补充说明
📊 点击打开驾驶舱：https://assistant.fire-matrix.com/
```

## 三、标准化存储字段体系（单层任务卡 `list_items`）

拍平后，所有信息全部统一、标准化地存在每一张任务卡（`list_items`）上；同一大项目的任务卡通过 `project_name` 轻量关联，便于按项目名检索和 OneDrive 自动归档到同一文件夹。

| 类别 | 卡片条目 | 底层字段名 | 说明与缺省规则 |
| :---: | :--- | :--- | :--- |
| 🔴 **必填** | **任务名称** | `title` | 清晰概括这件独立要办的事 |
| 🔴 **必填** | **归属项目/板块** | `project_name` + `work_domain` | 轻量归类标签（用于按项目筛选与 OneDrive 目录归档；杂事归「日常事务」） |
| 🔴 **必填** | **1）目标与交付成果** | `deliverable` | 最终要拿出的硬结果（写了什么文件、签了什么字、做了什么样机、通过什么测试）及验收标准 |
| 🔴 **必填** | **3）负责人 & 实施人** | `owner` + `assignee` | `owner`（总负责/拍板，默认预填 `徐宏玮`）；`assignee`（内部实际执行人，如 `王楠`、`李文颖`、`本人`） |
| 🔴 **必填** | **4）目标截止时间** | `planned_end_at` | 目标交付/验收日期（`YYYY-MM-DD`）；原文未指定时默认设为**任务建立后 3 个工作日**（自动跳过周末），不再反复弹出缺失提醒 |
| 🟡 选填 | **4）开始时间** | `planned_start_at` | 默认立项/交办当天，支持手动指定 |
| 🟡 选填 | **3）外部协作** | `external_partner` | 客户、设计院、供应商对接人（如 `韩工`），无则填 `无` |
| 🟡 选填 | **2）当前进度与已达成** | `milestone_stage` + `progress_log` | 当前阶段 + 带日期的时间线进展流水（`[MM-DD] ...`），每次汇报追加不覆盖 |
| 🟡 选填 | **5）卡点与关联档案** | `blocker_note` + `onedrive_doc_paths_json` | 等谁回复/卡在何处/风险提醒 + 自动挂接的图纸、文档或往来邮件 |
| 🟡 选填 | **6）补充备注（Comments）** | `comments` | **超出 1～5 条的所有客观补充信息**，按日期追加留痕，不覆盖历史 |
| 🟡 选填 | **7）CEO 评价** | `ceo_evaluation` | **董事长本人的主观评价、考核判断与批示**，按日期追加留痕，**严格仅限董事长本人私密可见** |

## 四、信息不全时的交互补全规则（先提醒、分必填选填、不卡顿）

当您发微信（文字/语音/转发聊天）或收到邮件触发新建任务卡时：

1. **自动提取**：AI 先把消息中已有的 `1）～5）`、`Comments` 和 `CEO 评价` 全部抽成标准结构。
2. **校验 5 项🔴必填**：检查 `任务名称`、`归属项目`、`目标与交付成果`、`实施人`、`目标截止时间`（负责人默认预填 `徐宏玮`）。
3. **缺🔴必填时，先提醒用户补全**（绝不瞎猜当天日期或编造人名）：
   ```text
   ⚠️ 任务信息还缺几项【必填】要素，请先补全后再正式建卡：
   - 缺失必填：1) 目标截止时间；2) 实施人
   - 选填可顺嘴补（不填也可）：外部协作、卡点、补充备注、CEO 评价

   👉 直接回复一句补全（例如：“实施人李文颖，截止下周五，交付国产替代BOM清单”）；
   👉 若此刻不便定，回复「先按待定建卡」也可先入卡（缺失项将标为【待补齐】在早报持续提醒）。
   ```
4. **建卡确认**：必填齐全（或老板明确允许先按待定建卡）后，按上述 `1）～7）` 标准格式发出待确认卡，回复 `1` 落盘，办完回复 `完成 #ID` 即彻底闭环。

## 五、日常微信快捷更新口令（追着单卡走）

- **办完闭环**：`完成 #1` 或 `#1 做完了`（整张任务卡闭合归档，不再出现在早间报告）
- **追加进展**：`#1 进展：已把点表发给韩工，等他周五前签字确认`（自动追加到 `2）当前进度与已达成`）
- **追加 CEO 评价**：`评价 #1：王楠推进偏慢，本周务必拿回确认件`（自动追加到 `7）CEO 评价`）
- **追加补充备注**：`备注 #2：排除金属屏蔽盖和外壳，只替板级 IC`（自动追加到 `6）补充备注`）
- **补齐缺失项/改排期**：`#2 截止改到 2026-12-05` 或 `改：...`
- **按项目名汇总查看**：`博州电厂还有哪些任务？`（按「归属项目」轻标签一键拉出关联任务卡）
