## 一、 FAST_ROUTER_PROMPT 是什么、从哪里来、怎么装配的？

1. 它是什么、从哪里来：
   - FAST_ROUTER_PROMPT 是静态维护在 src/wechat_assistant/prompts/system_prompts.py 中的系统级指令模板，负责充当智能体入口的第一道“分诊台”（调用轻量模型 qwen3.8-flash，备用 qwen-plus）。
   - 它不含任何真实密钥或业务隐私，随代码版本受控管理。
2. 每次收到消息时如何装配发送给大模型：
   在 src/wechat_assistant/graph.py 的 _node_guardrail_router 中，程序将以下两条消息拼装后请求模型：
   - system 消息：FAST_ROUTER_PROMPT 原文（定义 11 种意图、时间边界消歧规则、代词补全规则与禁止擅自联网调研规则）。
   - user 消息：由 ContextAssembler.render_for_router() 硬编码实时拼装，固定顺序为：
     【当前时间戳】 → 【跨天滚动会话摘要】 → 【相关项目上下文卡（若命中）】 → 【近期对话流与时间间隔（最近30轮）】 → 【当前待确认卡片（pending_proposals）】 → 【在途项目与待办快照（30项目/60待办）】 → 【用户最新输入】。

## 二、 路由器输出结构（IntentRoute）逐字段详解

路由器要求模型严格按 schemas.py 中的 IntentRoute 输出结构化 JSON，各字段作用如下：

1. intent（11 选 1 意图分类，决定下一跳节点）：
   - work_triage：明确的工作交办、转发聊天、语音想法、文件附件 → 进入阶段四起草确认卡
   - quick_query：查历史文档页码、旧报价、待办进度、或追问待确认卡原因 → 进入 3C 闭卷查档问答
   - conversational_chat：开放式讨论思路、问参谋建议，暂不建正式待办 → 进入 3B 多轮参谋对话
   - confirm_pending：有待确认卡时用自然语言同意（如“好的”“按这个办”） → 进入 3A 直接落盘
   - ideas_only_pending：只存想法孵化池，不建正式行动 → 进入 3A 仅存想法
   - discard_pending：取消或作废当前待确认卡 → 进入 3A 作废
   - revise_pending：要求修改待确认卡内容（如“改成下周五”“把帕莫瑞加上”） → 回阶段四重算
   - mutate_existing_item：汇报已有待办完成或开始（支持单条或一句话多条，如“#1 做完了，#2 开始了”） → 进入 3A 打卡并算跨度
   - undo：口语要求撤销刚落盘的操作 → 进入 3A 事务回滚
   - chitchat：纯寒暄（如“在吗”“辛苦了”） → 简短回应
   - clarify_or_unsupported（第 11 类兜底意图）：超出助理能力边界（如订机票、代发外部微信/邮件、执行终端命令）或语义过分模糊无法判断指代 → 进入澄清/边界说明节点，绝不强行乱建待办
2. resolved_intent_text（补全后的自包含意图）：把“他/它/这个/刚才那事”结合上下文翻译成独立完整的一句话，供下游检索与提案起草使用。
3. search_queries（1～3 个检索关键词）：提取最核心的项目名、人名、文件名或部件名，送入 FTS5 文档索引与历史对话检索。
4. target_item_id（目标待办编号）：当口语汇报完成/开始却没写 #ID 时，对照待办快照锁定对应数字编号。
5. needs_deep_research（是否允许公网检索）：提示词规定默认 false；代码层再加硬校验——仅原文显式含“查一下/上网查/联网搜/帮我查”时才允许为 true，否则一律强置 false。
6. clarify_question（澄清或拒答提示）：仅当 intent 为 clarify_or_unsupported 或置信度过低时填写，礼貌告知能力边界或追问 1 个关键细节。

## 三、 全链路异常处理与边界外情况兜底机制

针对“不在预设范围内”的请求或运行期可能出现的各类异常，系统按以下矩阵做全链路兜底：

| 异常 / 边界外场景 | 触发位置 | 系统的兜底处理机制 |
| :--- | :--- | :--- |
| 1. 超出能力边界或意图过于模糊（confidence < 0.55） | guardrail_router → clarify_or_unsupported | 拦截建单，由 clarify_or_unsupported 节点礼貌告知能力边界（不支持代发消息/订票等）或请用户补充 1 句项目/事项说明，绝不乱写待办。 |
| 2. 无待确认卡却口头说“确认/取消” | guardrail_router | 硬编码检测 pending_proposal 为空时，自动降级为 conversational_chat，避免报错或误删。 |
| 3. 大模型接口超时、限流或 JSON 格式畸形 | DashScopeLLMGateway | 自动指数退避重试 + 主备模型回退（例如 qwen3.8-flash → qwen-plus，qwen3.8-max → qwen-max）+ 正则提取修复畸形 JSON。 |
| 4. 主工作流发生未预期运行时异常 | graph.py _handle_incoming_turn_inner / wecom_gateway.py | 顶层 try/except 捕获异常（不泄露任何密钥），先把用户原话写入对话记录，再如实告知「本次没有生成待办或改动任何数据，原话已记入对话记录，可发“继续”或重发」，不静默崩溃。 |
| 5. 长任务处理耗时较长（12 秒以上） | web/app.py run_turn_with_heartbeat | 超过 12 秒自动发送实时阶段心跳，此后每 25 秒汇报当前进展，防止用户误以为后台假死。 |
| 6. 无法解析的附件格式（.dwg / 加密包 / 扫描件等） | storage/extractors.py | 拦截二进制乱码入库、只记元数据占位，100% 备份原件到 21Vianet OneDrive 00_原件收件箱/，依靠用户附言完成关联。 |
| 7. 语音消息转写失败或为空 | wecom_gateway.py | 转写失败时自动写入占位提示「收到语音消息，暂未能识别清晰文字，请补充文字说明」，不丢消息。 |
| 8. 外部邮件提示词注入或非白名单噪音邮件 | intake/mail_poller.py | 非 V&F / Tera / B&D 邮件与验证码/退订噪音直接跳过；命中邮件包裹 [UNTRUSTED_EXTERNAL_DATA] 边界并物理禁用 Shell 与外发工具。 |
| 9. 异构审计连续 2 轮仍未完全通过 | heterogeneous_critic | 达到 max_reflection_loops=2 上限后跳出死循环，将未消解疑点写入决策卡提醒董事长人工裁决。 |
| 10. 落盘错误或误确认 | db.py + atomic_executor | 每次确认均留存 24 小时 undo_snapshot_json，微信回复一句「撤销」即可原子回滚并重绘云端看板。 |
