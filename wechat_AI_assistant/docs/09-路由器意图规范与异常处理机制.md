## 一、 从 v2.0 `FAST_ROUTER_PROMPT` 到 v3.0 `FLAGSHIP_BRAIN_PROMPT` 的演进

1. **彻底取消独立路由模型**：旧版每次说话先由 `qwen3.8-flash` 塞进 16 个固定意图再交给下游节点，极易在多意图复合句或口语改卡时分类出错。v3.0 已将其彻底移除。
2. **唯一主脑系统提示词（`src/wechat_assistant/prompts/system_prompts.py`）**：
   - `FLAGSHIP_BRAIN_PROMPT` 集中定义于红区文件 `system_prompts.py`，由唯一主脑 `qwen3.8-max`（备选 `qwen-max`）读取执行；
   - 每轮由 `context_intake` 硬编码实时拼装发给主脑的上下文固定包含：
     **【确定性本周/下周日历锚点表】 → 【通道来源标记（微信/邮件）】 → 【跨天滚动会话摘要】 → 【相关项目上下文卡】 → 【近期真实对话流（最近 30 轮，绝不混入原始邮件正文）】 → 【当前待确认卡片完整内容】 → 【在途项目与待办快照（含 v2.0 1～7 栏）】 → 【用户最新输入或可信/不可信分框邮件批次】**。

## 二、 统一决策契约（`schemas.py` → `AgentDecision`）逐模式详解

主脑在完成必要的只读工具调用（`search_archive` / `read_doc_pages` / `check_workload_and_schedule` / `calc_business_date`）后，必须输出严格符合 Pydantic 强类型校验的 `AgentDecision` JSON：

| `mode` 枚举值 | 触发场景（全部由旗舰大脑自然理解） | 携带的核心字段与下游动作 |
| :--- | :--- | :--- |
| `propose` | 新建任务卡、修改待确认卡、汇总邮件批次、或纯知会邮件 | 携带 `proposal: TriageProposal`；若用户明确指示“改完顺便确认落盘”可置 `confirm_and_commit=True`（**仅当 3 条客观硬护栏 0 报错时才放行 1 步原子落盘**，有硬错则物理拦截）；若既无新任务也无已有任务更新则输出纯知会不建阻塞卡片。 |
| `confirm_pending` | 桌上有待确认卡且用户用自然语言同意（如“可以，按这个落盘吧”“先存成想法”） | `ideas_only: bool` → 签发 `ApprovalToken` 原子落盘并同步 OneDrive。 |
| `discard_pending` | 桌上有待确认卡且用户口语表示取消/作废 | 作废待确认卡并清理临时文件。 |
| `direct_ops` | 对已有任务做任意单条或复合操作（改截止日/负责人/实施人/阶段/卡点、追加 CEO 评价/备注/进展、开始/完成打卡、查沟通时间轴、24h 撤销） | 携带 `field_updates: list[TaskFieldUpdate]`、`note_appends: list[TaskNoteAppend]`、`status_changes: list[TaskStatusChange]`、`view_timeline_ids: list[int]`、`undo_last: bool`，在单轮内一次性全部执行并刷新云端看板。 |
| `reply` | 查历史文档页码（闭卷带出处）、参谋探讨思路、能力边界说明、或追问澄清 | 携带 `reply_text: str`，不改动正式待办与看板。 |
| `open_cockpit` | 要打开管理驾驶舱网址 | 返回固定驾驶舱链接 `https://assistant.fire-matrix.com/`。 |
| `show_workload` | 要看近 3 日日程分布与 Top 待办 | 返回只读日程汇总。 |

> **严格 Schema 兜底防线**：`AgentDecision._coerce_legacy_shapes` 仅兼容极少数历史扁平提案形态；凡遇到未识别结构的脏 JSON 一律显式抛出 `ValueError`，迫使 `DashScopeLLMGateway` 触发重试与备选模型切换，绝不静默吞错。

## 三、 极简 0 模型单字应急按钮（`_emergency_button_decision`）

严格遵循《大模型优先 + 确定性底盘》准则，**彻底清除所有自然语言与 `#ID` 正则截胡逻辑**（杜绝“#1 还没做完”否定句误写库与“#1 截止改到本周五”误报错）。`context_intake` 仅保留以下精确单字/单词离线应急控制按钮，其余一切自然中文与 `#ID` 指令全部直通旗舰大脑：
- 只读查询：`看板` / `驾驶舱` / `页面` / `dashboard`、`负荷` / `待办` / `今日待办` / `todo`
- 桌上有待确认卡时的单字签字：`1` / `确认`、`2` / `仅存想法`、`0` / `取消` / `放弃` / `作废`
- 24 小时安全撤销：`撤销`

## 四、 全链路 10 类异常与边界外兜底矩阵

| 异常 / 边界外场景 | 触发位置 | 系统兜底处理机制 |
| :--- | :--- | :--- |
| 1. 误触发送纯空白消息 | `graph.py` 入口 | 0 次模型调用，直接友好提示。 |
| 2. 桌上无待确认卡却说“确认/取消” | `action_executor` | 温和告知当前无待确认卡片，绝不报错或误操作正式库。 |
| 3. 大模型接口超时、503 或畸形 JSON | `DashScopeLLMGateway` + `_emergency_button_decision` | 自动指数退避重试 + 切换备选模型（`qwen3.8-max` → `qwen-max`）+ JSON 修复；应急按钮 0 模型照常工作。 |
| 4. 未预期运行时异常 | `graph.py _handle_incoming_turn_inner` | 顶层捕获并脱敏，先把用户原话记入对话库，再如实告知未改动任何数据，绝不静默崩溃。 |
| 5. 长任务处理超过 12 秒 | `web/app.py run_turn_with_heartbeat` | 12 秒首报当前步骤，此后每 25 秒汇报，结束即销毁；常规 5～8 秒零打扰。 |
| 6. 损坏/加密/不可解析附件（`.dwg`/坏 `.docx`/`.xlsx`/`.zip`） | `storage/extractors.py` | 拦截二进制乱码、安全限流解压（≤30 文件 / ≤50MB / 防路径穿越），优雅返回元数据占位并将原件 100% 备份至 OneDrive `00_原件收件箱/`。 |
| 7. 语音转写失败或回执超时 | `intake/wecom_gateway.py` | 语音转写失败写入兜底占位提示不丢消息；到达回执超时单独捕获，解析成功后再标 `MsgId` 已读。 |
| 8. 外部邮件提示词注入、噪音或下游瞬时故障 | `intake/mail_poller.py` | 域名过滤 + 可信块 `[SYSTEM_TRUSTED_MAIL_META]` 与不可信块 `[UNTRUSTED_EXTERNAL_DATA]` 物理分框；下游处理成功后才记 `seen_external_ids`。 |
| 9. 客观底盘护栏连续 2 轮仍不通过（如倒挂日期 / Outlook 抄送错派老板） | `flagship_brain` → `action_executor` | 满 2 轮硬熔断；若带 `confirm_and_commit=True` 则**物理拦截落盘**（`exec:blocked_dirty_commit`）；否则在确认卡显式标出「⚠️ 审计待人工复核点」交由董事长裁决。 |
| 10. 确认落盘时 OneDrive 云端 503 断网 | `db.py` + `commit_pending_proposal` | 本地 SQLite 单事务原子写入为唯一真值保底生效（留 24h 撤销快照）；云端同步报错单独捕获并如实告知稍后补刷，绝不回滚本地已落盘待办。 |
