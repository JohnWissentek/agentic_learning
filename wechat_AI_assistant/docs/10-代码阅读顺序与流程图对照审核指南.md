## 零、 「只读 10% 红区，管住 95% 质量」极速审核入口

v3.0 严格遵守个人独立开发者工程宪章：把最核心的数据契约、主脑提示词、客观底盘护栏与落盘安全门禁物理隔离在 **4 个短小精悍的 🔴 红区文件** 中，董事长或接手 AI 只需优先通读这 4 个文件，即可掌握系统全部规矩与底线：

| 优先级 | 🔴 红区核心文件 | 职责一句话 |
| :---: | :--- | :--- |
| **1** | `src/wechat_assistant/schemas.py` | 全部结构化契约：`AgentDecision`、`TriageProposal`、`ActionMutation`（含 `source_channel` 与 1～7 栏）、`TaskFieldUpdate/NoteAppend/StatusChange` |
| **2** | `src/wechat_assistant/prompts/system_prompts.py` | 全部大模型提示词集中地：`FLAGSHIP_BRAIN_PROMPT`（唯一主脑指令）+ `EPISODE_SUMMARY_PROMPT`（后台滚动摘要） |
| **3** | `src/wechat_assistant/nodes/critic_rules.py` | 极简 3 条纯客观底盘护栏（`objective_proposal_guard`）：合法公历日期且截止>=开始、显式通道锁定的 Outlook 仅抄送禁派老板、客观工时合理性（零字面子串误杀） |
| **4** | `src/wechat_assistant/tools/guard.py` | 写库与写云盘前必须验签的 HMAC-SHA256 `ApprovalToken` 与 `before_tool_callback` 门禁 |

## 一、 四步代码走读顺序（对照 v3.0 UML 2.5 状态机图）

### 第一步：读懂红区契约与网关（约 10 分钟）
1. `src/wechat_assistant/schemas.py`：核对 `AgentDecision.mode` 七种决策形态与 `_coerce_legacy_shapes` 严格校验逻辑。
2. `src/wechat_assistant/prompts/system_prompts.py`：核对 `FLAGSHIP_BRAIN_PROMPT` 中日历锚点使用、1 步改卡落盘、复合 `direct_ops`、禁止泄露内部黑话与纯 PMO 边界要求。
3. `src/wechat_assistant/config.py`：核对 `DashScopeLLMGateway` 主备切换、重试与 `assert_no_secrets_leaked` 输出脱敏检查。

### 第二步：顺着 UML 2.5 状态图走完 3 节点主干（核心审核区）
4. `src/wechat_assistant/intake/wecom_gateway.py` & `mail_poller.py`：
   - 核对企微单人白名单、2 秒静默合并、语音 `qwen3-asr-flash` 转写与到达回执；
   - 核对 `mail_poller.py` 的 `config/mail_domains.json` 域过滤、完整 2500 字正文提取、`infer_email_role_hint` 与 `[SYSTEM_TRUSTED_MAIL_META]` / `[UNTRUSTED_EXTERNAL_DATA]` 物理分框。
5. `src/wechat_assistant/context_assembler.py`：
   - 核对 4 层上下文装配（滚动摘要 + 近 30 轮对话 + 待确认卡 + 在途任务快照含 1～7 栏与 `mail_conversation_ids`）及 FTS5 双路检索。
6. `src/wechat_assistant/graph.py`（v3.0 极简 3 节点引擎）：
   - 先看 `build_calendar_anchor_text()`：确认昨天、今天（周几）、明天、本周一~日、下周一~日由 Python 确定性生成；
   - 再看 `_build_graph()`：仅有 `context_intake` → `flagship_brain`（自纠 ≤2 轮） → `action_executor` → `END` 三个节点；
   - 核对 `_node_context_intake()`：附件前置入库 + 4 层上下文 + `_emergency_button_decision()` 极简 0 模型应急直通；
   - 核对 `_node_flagship_brain()`：单一 `qwen3.8-max` 原生工具调用（`search_archive` / `read_doc_pages` / `check_workload_and_schedule` / `calc_business_date`，≤4 轮）+ `objective_proposal_guard` 3 条客观护栏；
   - 核对 `_node_action_executor()`：`one_step_commit`（有硬错物理拦截 `exec:blocked_dirty_commit`）、`commit_pending_proposal`（强制 `source_channel` 归属与 `ApprovalToken` 验签）、`_execute_direct_ops`（复合改多条任务）与 `format_decision_card`（单任务隐藏冗余摘要、过滤系统噪点）。

### 第三步：核查受控只读工具与存储同步
7. `src/wechat_assistant/tools/memory_tools.py` & `schedule_tools.py`：只读检索与纯 Python 工作日/排期密度计算。
8. `src/wechat_assistant/tools/onedrive_tools.py`：世纪互联 OneDrive 分片上传与 5 份 `.md` 看板渲染（含 `[微信]`/`[邮件]`/`[驾驶舱]` 来源标签）。
9. `src/wechat_assistant/storage/extractors.py`：PDF/Word/Excel/CSV/ZIP 安全限流解析与损坏兜底。

### 第四步：按需抽查 SQLite 与 Web 驾驶舱
10. `src/wechat_assistant/storage/db.py`：核对 `source_channel` 无损迁移、`apply_proposal_atomic`、幂等 `append_task_timeline`、`undo_last_commit` 与 `dashboard_overview`。
11. `src/wechat_assistant/web/app.py` & `web/static/index.html`：核对 6 位验证码限流鉴权、12s/25s 心跳、早晚简报与整点邮件定时任务，以及前端来源徽标与 `#filter-source` 筛选器。

## 三、 本地一键全量验证命令（125 条单测 + 14 条黄金轨迹 + 8 条真模型 E2E）

在 `wechat_AI_assistant/` 目录下执行：

```bash
uv run pytest -v --tb=short && uv run python -W error::ResourceWarning scripts/replay_golden_traces.py
# 真实百炼 qwen3.8-max 端到端 E2E 实弹验收（隔离临时库，不发真实微信/不写网盘）：
uv run python scripts/e2e_live_flagship_brain.py
```

关键测试模块分布：
- `tests/unit/test_v3_model_first_audit_fixes.py`（9 条）：Model-First 盲审 P0/P1 防回归黑盒契约测试（验证否定句与相对日期不被死正则截胡、邮件边界标签逃逸注入防护、纯客观护栏无字面子串误杀与显式通道锁、`Asia/Shanghai` 显式时区、原生多轮 Tool Calling 与末轮收敛、`fast` 档摘要乐观锁、企微 502 降级与三阶段进度回调）。
- `tests/unit/test_v3_single_brain_agent.py`（7 条）：v3.0 单脑旗舰 Agent 黑盒契约测试（验证 0 次路由/二审调用、五彩湾两轮“昨天+周五一步落盘”、微信 vs Outlook `cc_observer` 通道隔离、复合 `direct_ops`、单任务极简卡片、脏落盘物理拦截、503 断网单字应急按钮）。
- `scripts/e2e_live_flagship_brain.py`（8 条）：调用真实百炼 `qwen3.8-max` 实弹验证五彩湾 2 轮、否定句防误改、单句复合 3 操作、相对日期修改、闭卷查档引用、Outlook 抄送边界注入防御与单脑零失败遥测。
- `tests/unit/test_source_channel_badge.py`（4 条）：`source_channel` 数据库无损迁移、自动打标、早报展示与 Web 前端徽标/筛选。
- `tests/unit/test_clean_slate_and_audit_fixes.py`（10 条）& `test_task_card_v2_and_mail_roles.py`（11 条）：冷启动清库安全、可信/不可信分框、邮件角色推断、会话号自动回填与幂等时间轴。
- `tests/unit/test_mail_hourly_window.py`（14 条）& `test_full_scenarios_and_exceptions.py`（19 条）& `test_pmo_and_stage_resilience.py`（10 条）& `test_core_workflow.py`（25 条）& `test_config_and_guard.py`（5 条）& `tests/trajectory/test_trajectories.py`（10 条）& `tests/regression/test_golden_rubric.py`（1 条）：全链路回归与异常韧性覆盖。
- `scripts/replay_golden_traces.py`（14 条）：G01–G14 董事长真实与极端异常场景端到端回放体检。
