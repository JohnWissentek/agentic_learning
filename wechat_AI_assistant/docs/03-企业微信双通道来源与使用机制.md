## 一、 一句话看懂来源出处与相互关系

你在绿色个人微信里看到的两个入口——「个人幕僚室 → AI工作助理」与「客服消息 → AI_assistant客服」——并不是两套独立系统，而是来自你在企业微信注册的同一家企业主体（个人幕僚室）下的两种不同官方能力，且它们背后连着阿里云上的同一个 AI 大脑、同一个数据库与同一个世纪互联 OneDrive 私有库。

```text
企业微信主体（相当于你的“公司”）：个人幕僚室（CorpID）
  │
  ├── 【来源 1：内部办公能力】应用管理 → 自建应用 → AI工作助理（AgentId）
  │     └── 通过「微信插件（微工作台）」扫码投影进你的绿色个人微信首页
  │         （表现形态：首页可置顶「个人幕僚室」，点进去就是「AI工作助理」）
  │
  └── 【来源 2：对外接待能力】应用管理 → 微信客服 → AI_assistant客服（open_kfid）
        └── 企业微信自带的“微信客服”功能（原设计用于接待外部微信客户咨询）
            （表现形态：个人微信会自动把它收进首页的「客服消息」系统折叠盒子里）
              │
              ▼   （两条官方加密回调通道最终汇入同一台服务器）
      阿里云 ECS（同一个 FastAPI 服务 + 同一个 SQLite + 同一个 21Vianet OneDrive）
```

形象比喻：个人幕僚室是你注册的公司名称，AI工作助理是公司内部专门为你服务的专属办公窗口，AI_assistant客服是公司门口接待外部来客的客服前台；但两个窗口后面坐着的是同一个人（同一套 AI 幕僚大脑）。

## 二、 两条通道各自能实现的功能与官方硬限制

腾讯对「内部自建应用」与「外部微信客服」给了截然不同的官方权限与限制（属于微信平台规则，代码层无法绕过）：

| 对比维度 | 主力通道：个人幕僚室 → AI工作助理（自建应用 + 微信插件） | 备用通道：客服消息 → AI_assistant客服（微信客服） |
| :--- | :--- | :--- |
| 后台来源出处 | 企业微信「应用管理 → 自建应用」 + 「微信插件」 | 企业微信「应用管理 → 微信客服」 |
| 个人微信首页置顶 | 支持直接置顶在首页，一眼找到 | 不支持置顶，强制收进「客服消息」折叠盒子 |
| 转发联系人列表直选 | 支持，多选聊天记录点转发可直接搜索选中 | 不支持，转发联系人列表里搜不到客服账号 |
| 收发语音、文字、图片、PDF/Excel | 完全支持（语音 <0.5s 回执 + 自动转写） | 完全支持 |
| 接收多选「逐条转发」 | 支持，服务器停手等 2 秒自动合并为同一件事处理 | 支持 |
| 接收打包「合并转发」卡片 | 不支持（腾讯禁止自建应用直接接收 [聊天记录] 卡片） | 支持，可直接解析原生的 [聊天记录] 合并转发卡片 |
| 早 08:30 / 晚 18:00 主动推简报与盘点 | 7×24 小时随时主动推送，永不断流 | 受限：仅用户主动发消息后的 48 小时内最多被动回复 5 条 |
| 电脑端驾驶舱收 6 位登录验证码 | 随时可主动发送，不受时间限制 | 受限：超过 48 小时未互动会被腾讯接口拦截 |
| 单人权限隔离方式 | 企业微信后台应用「可见范围」仅勾选董事长本人 1 人 | 后端代码通过 owner_external_userid 白名单硬拦截 |

## 三、 为什么不建议只留「客服消息」单一通道？

如果为了图省事，只保留「客服消息 → AI_assistant客服」而停用「个人幕僚室 → AI工作助理」，会遇到三个影响日常核心体验的硬伤：

1. 早晚简报与每日 18:00 主动进度盘点会经常断流：周末两天或出差忙起来只要超过 48 小时没给它发消息，周一早上 08:30 的早间简报、傍晚 18:00 的「今日进度盘点」以及电脑浏览器登录驾驶舱请求的 6 位验证码，都会因为超过腾讯 48 小时客服回复窗口而被拦截发送失败。
2. 不能置顶，容易被其他消息淹没：只要你平时收过快递、电商、银行等商家的客服消息，AI_assistant客服就会在「客服消息」盒子里被往下顶。
3. 群聊转发不够顺手：在群聊里长按多选消息点转发时，搜不到客服账号，必须先点进「客服消息」盒子或扫码进入。

相反，如果希望彻底简化为真正的单一通道，正确的减法是：只留「个人幕僚室 → AI工作助理」，把「客服消息」当成不存在（甚至在后台停用）。只要平时多选聊天记录时点左边的「逐条转发」，即可保住置顶、定时简报、18:00 主动盘点与 6 位验证码全部核心能力。

## 四、 两条通道的日常配合使用方法

### 4.1 日常主力使用（覆盖 99% 场景）：只用「个人幕僚室 → AI工作助理」
1. 在绿色个人微信首页置顶「个人幕僚室」。
2. 日常发语音想法、发图片/PDF/Excel 报价单、查历史文档页码、接收早晚简报、响应 18:00 主动进度盘点、收驾驶舱链接或 6 位验证码，全部在这个窗口完成。
3. 当你需要把某个微信群或私聊的多条讨论转给助理时，长按多选聊天记录 → 点击左下角「逐条转发」→ 选择「个人幕僚室 → AI工作助理」发送即可。发完后无需任何额外口令，停手等 2 秒服务器会自动把这批消息合并为同一件事处理（如果赶时间连 2 秒都不想等，才可选发一句「好了」提前结束等待）。

### 4.2 特殊情况备用（覆盖 1% 场景）：临时用「客服消息 → AI_assistant客服」
1. 唯一触发场景：别人已经把几十条群聊记录打包成了一张完整的 [聊天记录] 合并转发卡片发给你，你不想点进去一条条拆开逐条转发，只想把整张卡片直接甩给助理。
2. 操作方法：把那张合并转发卡片转发给个人微信「客服消息」盒子里的 AI_assistant客服（或扫一次它的客服二维码发送）。
3. 协同效果：它背后的服务器大脑、上下文记忆、SQLite 清单和世纪互联 OneDrive 与主力入口完全一致，分析完的确认卡同样会进你的工作区；之后确认或查看进度，回到置顶的「个人幕僚室 → AI工作助理」或 Web 驾驶舱即可。

## 五、 扩展能力：个人幕僚室下的多助理架构

基于同一套企业微信「个人幕僚室」主体，未来如果业务需要，可以在企业微信后台继续新增第 2 个、第 3 个自建应用（每个应用都是「个人幕僚室」里的一个独立助理窗口，各自拥有独立的后端回调与权限边界）：
- 1 号助理（当前已上线）：AI工作助理，专注董秘项目管理、四大清单、周期跨度追踪、内部档案检索与 21Vianet 归档，严格不越位代做外部调研。
- 2 号助理（按需扩展）：例如“外勤市场调研助理”，未来可专门连接具备公网检索权限的独立沙箱，同时在物理上完全剥夺它访问公司邮箱和内部私有 OneDrive 的权限，实现“内账董秘”与“外勤研究员”的彻底隔离。
