## 一、 极简阿里云单机部署拓扑

去掉 Odoo 耦合、去掉自建 OSS 与第三方同步盘后，整套系统**只需要 1 台轻量阿里云 ECS 即可 7×24 完整运转**：

- **运行主机**：呼和浩特阿里云 ECS `firematrix`（2 核 4G，Ubuntu 24.04，60G 系统盘目前仅用约 16%，详见本地 `env/.env.ecs`）。该机已运行轻量官网 `firematrix-web`（端口 3000），本助理以独立非特权系统用户 `wxagent` 跑 `systemd` 后台单实例服务。
- **为什么必须放云端 ECS 而不是只跑家里/办公室电脑**：
  1. 微信长连接与工作邮箱增量监听必须全天候在线，你在外地、开车或出差时随手转发才能秒回；
  2. 国内骨干网直连企业微信网关、阿里云百炼（华北 2 北京地域）与微软 Graph API 均稳定可靠；
  3. 附件传上企业 OneDrive 校验完成后即清理 ECS 本地临时文件，60G 系统盘毫无扩容压力。

## 二、 企业核心信息防外泄「六道硬防线」

这套系统收口的是老板最核心的客户名单、底价、研发参数与未公开战略想法。以下六道防线**从通信入口、大模型、网盘权限、服务器、代码库到外发能力全面锁死**：

### 防线 1：入口与后台组织隔离（防内部越权 & 第三方平台风险）
- **官方空壳传声筒**：企业微信「API 模式智能机器人（长连接）」+「微信插件」仅作为加密转发通道，**不开腾讯自带 AI、不存业务数据在企微后台**；服务端直接用纯 Python `websockets` 标准库自建连接，**不接入任何第三方开源聊天 Bot 平台**。
- **可见范围锁死 1 人**：机器人可见范围只选你本人 1 个账号；更推荐用你的手机号**免费独立注册一个“仅你 1 人的专属企业微信主体”**，连公司 IT 管理员也完全看不见这个机器人的任何管理配置或日志。

### 防线 2：大模型隐私保护 +「`密：` 前缀」零出网直存（防模型侧留存）
- **百炼商业标准 API 不用于训练**：使用你自己阿里云主账号下的百炼标准按量付费 API，阿里云官方合规协议明确**不会将 API 输入与输出数据用于任何大模型训练**，传输与存储均走 TLS / AES-256 加密；同时在百炼控制台不开启任何实验性数据共享/调优授权，**绝不接入 LangSmith 等第三方云端观测平台**。
- **绝密内容「`密：` 前缀」硬拦截（重要）**：遇到核心算法源码、核心传感器工艺配方、敏感股权/薪资协议等连云端商业 API 都不想触碰的内容，在微信发送时加上 **`密：`** 开头——服务端代码直接拦截，**1 个字节都不发往百炼 API**，直接加密存入 OneDrive 隔离目录（后续可扩展为经 Tailscale 加密专线转交你本地办公室 **Mac Studio M2 Ultra** 上离线跑的开源千问模型处理，正文不出你自己的硬件）。

### 防线 3：企业 OneDrive 沙箱目录最小权限锁死（防网盘误删与越权）
- **严禁授予 `Files.ReadWrite.All`**：只申请 **`Files.ReadWrite.AppFolder`**（将程序锁死在 `/应用/AI幕僚归档库/` 单个目录内，你 OneDrive 里的其他全部文件夹程序连名字都读不到）或仅对单个私有库授权 **`Sites.Selected`**。
- 整个归档库默认仅你本人账号可见；只有在 Mac 上你主动右键分享某个具体项目文件夹时，特定同事才能看到该子目录。

### 防线 4：网络零端口暴露与凭据大扫除（防外部黑客）
- **零公网入站端口**：企业微信长连接、邮箱拉取、百炼调用、Graph 上传全部是 ECS **主动对外发起的出站加密连接**，安全组不需要放行任何入站端口，彻底隔离公网扫描与攻击。
- **上线前必做安全整改**：
  1. 立即作废 `env/.env.bailian` 里曾在旧仓库记录过的百炼 Key，在阿里云百炼控制台新建专用 Key（建议命名 `wechat-assistant-prod`）并设置月度消费上限预警；
  2. 为 `firematrix` 生成专用 SSH Ed25519 密钥并修改旧 `root` 密码，确认密钥登录无误后关闭 SSH 密码登录；
  3. 服务器环境变量 `/etc/wechat-agent/env` 权限锁死 `640`（属主 `root:wxagent`）；
  4. `journalctl` 应用日志只记消息编号、阶段状态、耗时与错误码，**严禁打印任何聊天正文、邮件正文与密钥**。

### 防线 5：Git 仓库与业务数据物理隔离（防误推送泄密）
- GitHub 仓库**只存纯程序代码与架构设计文档**。
- 所有 SQLite 数据、临时附件缓存全在服务器 `/opt/wechat-agent/data` 与企业 OneDrive，绝不进入任何 Git 工作区；根仓库 `.gitignore` 持续锁死 `**/.env.*`、`*.key`、`*secret*`、`*token*`、`*.pdf`。

### 防线 6：物理阉割「对外发信与群发」能力（防 AI 幻觉误外泄）
- **邮箱绝不配发信权限**：Microsoft Graph 仅授予 `Mail.Read`（只读），或 IMAP 只读连接，**绝不授予 `Mail.Send` 也不配 SMTP**。
- **微信只对本人单聊**：机器人不入业务群、不代表你回复任何客户。哪怕模型偶发理解偏差，也只会在你自己的私人聊天窗口里多弹一张预览卡，**物理机制上 100% 不可能向外部客户或供应商发错任何敏感信息**。

## 三、 服务端环境变量模板 (`/etc/wechat-agent/env`)

以下为部署在 `firematrix` 上的配置文件模板（所有真实凭据仅在部署时写入服务器本地，切勿写进代码或文档）：

```ini
# --- 1. 运行基础 ---
TZ=Asia/Shanghai
DATA_DIR=/opt/wechat-agent/data
TMP_CACHE_DIR=/opt/wechat-agent/tmp_cache
LOG_LEVEL=INFO
DISK_ALERT_PERCENT=80

# --- 2. 微信通道（企业微信智能机器人长连接） ---
WECOM_BOT_ID=<企微智能机器人 BotID>
WECOM_BOT_SECRET=<企微智能机器人长连接 Secret>
SEGMENT_QUIET_SECONDS=60              # 逐条转发静默合并窗口（秒）

# --- 3. 阿里云百炼大模型 ---
DASHSCOPE_API_KEY=<新生成的百炼专用 API Key>
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_MODEL=qwen3.8-max
QWEN_SNAPSHOT_MODEL=qwen3.8-max-0902

# --- 4. 企业 Office 365 OneDrive & 邮件（Microsoft Graph） ---
MS_CLOUD_ENV=global                   # global（国际版）或 china_21vianet（世纪互联版）
MS_TENANT_ID=<Office 365 租户 ID>
MS_CLIENT_ID=<Azure/Entra 应用 Client ID>
MS_CLIENT_SECRET=<应用 Client Secret（Sites.Selected 模式使用；AppFolder 可留空或配机密客户端）>
MS_PERMISSION_MODE=app_folder         # app_folder（个人沙箱目录）或 sites_selected（独立站点库）
MS_SITE_ID=<仅 sites_selected 模式填写>
ONEDRIVE_ROOT_FOLDER=AI幕僚归档库

# --- 5. 工作邮箱自动拉取（第二阶段启用，物理只读） ---
MAIL_ENABLED=false
MAIL_PROVIDER=graph_mail              # graph_mail（复用上述 Graph Mail.Read）或 imap
MAIL_POLL_INTERVAL_SECONDS=120
# 若用标准 IMAP 则额外填写：
IMAP_HOST=<IMAP 服务器地址>
IMAP_PORT=993
IMAP_USER=<工作邮箱>
IMAP_PASSWORD=<只读客户端授权码>

# --- 6. 确认模式与每日简报 ---
CONFIRM_MODE=preview_card             # preview_card（回1确认）或 auto_with_undo（高把握自动+24h可撤销）
DAILY_MORNING_DIGEST=08:30
DAILY_EVENING_DIGEST=18:00
```

## 四、 三阶段敏捷实施路线图

由于去掉了 Odoo 对接与复杂同步组件，整套系统的开发与上线周期大幅缩短：

### 第一阶段：微信 + 语音闪念 → 百炼单卡分拣 → SQLite 清单 & 企业 OneDrive 直写（MVP，2～3 天）
1. **安全前置**：轮换百炼 API Key、加固 `firematrix` SSH 密钥登录，在 Microsoft Entra（Azure AD）创建专属应用并授权 `Files.ReadWrite.AppFolder`（或 `Sites.Selected`）。
2. **微信长连接打通**：在 `firematrix` 启动轻量 Python 接收端，个人微信置顶「工作助理」，完成 **T1–T3 转发方式与字数上限实测**。
3. **极简核心闭环上线**：上线 60 秒合并、百炼 `qwen3.8-max` 单卡分拣与数字保真硬核验、`密：` 前缀拦截、3 表 SQLite，以及 Microsoft Graph 异步分片上传 OneDrive（含 `00_我的四大清单/*.md` 自动更新与 `撤销` 能力）。回到 Mac 打开 Finder / Obsidian 即刻验证同步效果。

### 第二阶段：企业工作邮箱全自动接入（第 2 周）
1. 打开 `MAIL_ENABLED=true`，接入 Office 365 `Mail.Read`（或只读 IMAP）增量拉取与垃圾/验证码过滤规则；
2. 补齐 PDF（按页提取）、Word、Excel、图片 OCR 文本提取入库 `sources_fts`，让所有邮件附件自动重命名归入 OneDrive 并支持内页全文检索；
3. 上线邮件中金额、交期变化与历史记录的新旧对照冲突提醒。

### 第三阶段：深度历史问答、简报打磨与本地离线算力扩展（第 3 周）
1. 开放跨微信 + 邮件 + PDF 页码的带出处深度问答工具链；
2. 上线工作日早 `08:30` / 晚 `18:00` 微信简报（含待办、等待催办、周五想法孵化池回顾）；
3. （可选）按实际手感微调是否切换为「模式 B 高把握自动入库」，以及将 `密：` 前缀内容经 Tailscale 专线转交本地 Mac Studio 离线模型自动提炼摘要。

## 五、 开工前只需拍板的 3 个配置信息

正式动手写代码前，确认下面三件事即可直接开干：

1. **你的企业 Office 365 属于哪种版本？**（**国际版**还是**世纪互联中国版**？以及你的主力工作邮箱是否就在这套 Office 365 里？）
2. **企业微信主体选择**：是在现有企业里只给你 1 个人开「API 模式智能机器人」，还是用手机号另免费注册一个**仅你 1 人的独立企业微信**做完全后台隔离？
3. **默认确认方式**：选 **模式 A**（每件事发 1 张预览卡，回 `1` 确认入库），还是 **模式 B**（高把握自动归档并回执，仅拿不准或冲突时询问）？
