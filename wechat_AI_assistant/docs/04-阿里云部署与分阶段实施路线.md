## 一、 极简阿里云单机部署拓扑

尽管智能体内部按《Agentic Design Patterns》配齐了三档推理模型、四大受控工具箱和 LangGraph 检查点，但整套软件依然**只运行在 1 台轻量阿里云 ECS 上**，无任何重型中间件：

- **运行主机**：呼和浩特阿里云 ECS `firematrix`（2 核 4G，Ubuntu 24.04，60G 系统盘目前仅用约 16%，详见本地 `env/.env.ecs`）。该机当前运行轻量官网 `firematrix-web`（端口 3000），本助理以独立非特权系统用户 `wxagent` 跑 `systemd` 后台单实例服务。
- **单机承载全部核心闭环**：企微长连接 + Graph Mail/IMAP 只读拉取 + 本地 SQLite（`app.db` & `checkpoints.db`）+ 百炼三档模型调用（`qwen3.8-flash` / `qwen3.8-max` / `deepseek-v4-pro` 均可经同一百炼 OpenAI 兼容端点调用）+ Microsoft Graph 异步上传企业 OneDrive。
- **为什么放云端 ECS**：保证 7×24 秒收微信与工作邮件、国内骨干网直连各接口稳定；且大文件传入 OneDrive 校验完成后即清本地缓存，60G 磁盘常年宽裕。

## 二、 企业核心信息防外泄「六道硬防线」（含 Ch.18 纵深护栏）

本系统收口老板最核心的客户名单、底价、研发参数与战略设想，下面六道防线从物理通道、模型与工具护栏、网盘权限、服务器、代码库到外发能力全链路锁死：

### 防线 1：入口与后台组织隔离（防内部越权 & 通用外壳风险）
- **官方空壳传声筒**：企业微信「API 模式智能机器人（长连接）」+「微信插件」仅做加密透传，**不开腾讯自带 AI、不存业务数据在企微后台**；服务端直接自研干净的 Python 内核，**不套 OpenClaw / Hermes 等带裸终端风险的通用壳**。
- **可见范围锁死 1 人**：机器人可见范围只选你本人 1 个账号；更推荐用个人手机号**免费另建一个“仅你 1 人的专属企业微信主体”**，与公司企业微信彻底隔离。

### 防线 2：大模型隐私 +「`密：` 前缀」零出网 + Ch.18 护栏（防模型留存与邮件注入）
- **百炼商业标准 API 不用于训练**：使用你自己阿里云主账号下的标准按量付费 API（含千问与 DeepSeek 系列模型），官方合规协议承诺输入与输出绝不用于训练任何大模型，全程 TLS / AES-256 加密；同时**绝不把含正文的生产数据发往 LangSmith 等公有云观测平台**（如需可视化追踪，仅在本地或经 Tailscale 内网回传到你自建的私有 `agentic_observability_hub`）。
- **绝密内容「`密：` 前缀」硬拦截**：遇到核心算法源码、核心工艺配方、敏感股权/人事协议，发送时加 **`密：`** 开头——输入护栏在代码层物理拦截，**1 个字节都不出给百炼或任何外部搜索**，直接加密存进 OneDrive 隔离目录（未来可经 Tailscale 转交办公室本地 **Mac Studio M2 Ultra** 离线开源模型处理）。
- **防御外部邮件提示词注入（Ch.18）**：所有拉取的邮件正文和 PDF 提取文本在进入模型上下文前，统一包裹在明确的数据边界标签（`[UNTRUSTED_EXTERNAL_DATA]`）内；同时**系统物理上不提供 Shell 执行工具与发信工具**，哪怕外部垃圾邮件藏了恶意诱导指令，模型也毫无越权破坏路径。
- **脱敏外搜前置拦截 + 防 System Prompt 泄露**：`search_public_tech_intel` 在出网查询前必须过脱敏校验器，剥离一切客户全称、合同号与价格数字（并可通过 `EXTERNAL_SEARCH_ENABLED=false` 一键关闭全网搜索）；System Prompt 严禁硬编码任何密钥、私有 URL 或核心商业底数。

### 防线 3：企业 OneDrive 沙箱目录最小权限锁死（防网盘误删与越权）
- **严禁授予 `Files.ReadWrite.All`**：只申请 **`Files.ReadWrite.AppFolder`**（程序在微软底层只能读写 `/应用/AI幕僚归档库/` 单个文件夹，完全看不见你 OneDrive 里的其他目录）或仅授权单个私有库 **`Sites.Selected`**。
- 整个归档目录默认仅你本人可见；仅当你在 Mac 上主动右键分享某个子文件夹给指定同事时才对外协同。

### 防线 4：网络零端口暴露与凭据大扫除（防外部黑客）
- **零公网入站端口**：所有连接全部是 ECS **主动对外发起的出站加密连接**，安全组不需要放行任何入站端口。
- **上线前必做安全整改**：
  1. 立即作废 `env/.env.bailian` 里曾在旧仓库记录过的百炼 Key，在阿里云百炼控制台新建专用 Key 并设消费预警；
  2. 为 `firematrix` 生成专用 SSH Ed25519 密钥、改新密码后关闭 SSH 密码登录；
  3. 服务端 `/etc/wechat-agent/env` 权限锁死 `640`（属主 `root:wxagent`）；
  4. `journalctl` 运行日志只记线程 ID、节点耗时与错误码，**严禁打印任何聊天/邮件正文或密钥**，代码内接入 `assert_no_secrets_leaked` 防泄密断言。

### 防线 5：Git 仓库与业务数据物理隔离（防误推送泄密）
- GitHub 仓库**只存纯程序代码、测试脱敏样例和架构设计文档**。
- 所有真实 SQLite 数据与缓存全在 ECS `/opt/wechat-agent/data` 与企业 OneDrive，根仓库 `.gitignore` 锁死 `**/.env.*`、`*.key`、`*secret*`、`*token*`、`*.pdf`。

### 防线 6：物理阉割「对外发信与群发」能力（防 AI 幻觉误外泄）
- 邮箱只配 `Mail.Read`（或只读 IMAP），**绝不配置 `Mail.Send` 与 SMTP**；机器人只在单聊向你本人汇报，物理机制上 100% 不可能替你对外乱发消息。

## 三、 服务端环境变量模板 (`/etc/wechat-agent/env`)

以下为部署在 `firematrix` 上的配置文件模板（所有真实凭据仅在部署时填入服务器本地，切勿写进代码或文档）：

```ini
# --- 1. 运行基础 ---

TMP_CACHE_DIR=/opt/wechat-agent/tmp_cache

DISK_ALERT_PERCENT=80

WECOM_BOT_ID=<企微智能机器人 BotID>
WECOM_BOT_SECRET=<企微智能机器人长连接 Secret>
SEGMENT_QUIET_SECONDS=60

# --- 3. 阿里云百炼三档异构模型（统一 OpenAI 兼容网关 + 主备回退） ---
DASHSCOPE_API_KEY=<新生成的百炼专用 API Key>
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
FAST_MODEL=qwen3.8-flash
FAST_FALLBACK_MODEL=qwen-plus
PRODUCER_MODEL=qwen3.8-max
PRODUCER_FALLBACK_MODEL=qwen-max

DAILY_MORNING_DIGEST=08:30
DAILY_EVENING_DIGEST=18:00
```

## 四、 三阶段敏捷实施路线与 Ch.19 自动化质量门禁

### 第一阶段：强推理 MVP 闭环上线（3～4 天）
1. **安全前置**：轮换百炼 API Key、加固 `firematrix` SSH 密钥登录，注册 Microsoft Entra 应用（`Files.ReadWrite.AppFolder` 或 `Sites.Selected`）。
2. **微信长连接实测**：在 `firematrix` 起轻量接收端，个人微信置顶「工作助理」，完成 **T1–T3 转发实测**。
3. **《Agentic Design Patterns》内核 + OneDrive 落盘**：上线 `LangGraph` 有界闭环、`DashScopeLLMGateway` 三档异构配对（`qwen3.8-flash` / `qwen3.8-max` / `deepseek-v4-pro`）、`密：` 前缀直存、精算工具沙箱（日期+Excel Diff）、3+1 表 SQLite 及 Microsoft Graph 异步分片上传 OneDrive（自动渲染 `00_我的四大清单/*.md` + `撤销`）。

### 第二阶段：工作邮箱自动接入 + 脱敏并发调研（第 2 周）
1. 打开 `MAIL_ENABLED=true`，接入 Office 365 `Mail.Read`（或只读 IMAP）+ 防注入数据隔离包裹；
2. 补齐 PDF 按页提取、Office 与图片 OCR 全文入库 `sources_fts`（可选加轻量向量列补齐混合检索）；
3. 按需开启 `EXTERNAL_SEARCH_ENABLED=true`，让想法语音闪念自动附带脱敏外部公开技术简报写入 OneDrive。

### 第三阶段：Ch.19 自动化评估门禁 + 日常进化打磨（第 3 周）
在每次修改提示词、升级模型版本或调整工作流前，必须通过 **Ch.19 三层质量门禁**：
1. **确定性单测与护栏门禁**：数字保真 100%、`assert_no_secrets_leaked`、Excel 精算精度、脱敏外搜过滤、`before_tool_callback` 拦截验证；
2. **轨迹评估（`Trajectory Eval`）**：用脱敏黄金样例加 Mock 工具，核对智能体是否按预期选择了检索、精算或外搜工具及参数传递顺序；
3. **`LLM-as-a-Judge` 黄金回归集**：由独立裁判模型对照 Rubric 对切分、冲突识别、带页码问答准确性打分，不低于基线才发布切换；并上线早晚 `P0–P2` 动态优先级简报与个人规则自进化（Ch.8）。

## 五、 开工前只需拍板的 3 个配置信息

正式动手写代码前，确认以下三项即可立刻启动第一阶段开发：

1. **企业 Office 365 版本与邮箱归属**：你的企业 Office 365 是**国际版**还是**世纪互联中国版**？主力工作邮箱是否也在同一套 Office 365 里？
2. **企业微信主体选择**：是在现有企业里只给你 1 个人开「API 模式智能机器人」，还是用手机号另免费注册一个**仅你 1 人的独立企业微信**做完全后台隔离？
3. **默认确认与外搜偏好**：确认模式先选 **模式 A**（1 张高密度决策卡回 `1` 落盘），还是 **模式 B**（高把握自动落盘 + 随时可`撤销`）？第一阶段是否同步开启 **脱敏外部技术调研（Metaso/Serper）**？
