## 一、 阿里云部署拓扑（为什么部署在云端）

本系统采用**全阿里云云端常驻部署**，而不是跑在个人电脑上：
- **24 小时在线收口**：微信长连接与邮箱后台 IMAP 监听必须 7×24 运行，你在外地、开车或出差时发给机器人的语音与转发才能秒级响应。
- **国内骨干网低延迟**：阿里云 ECS ↔ 阿里云百炼（北京地域）↔ 阿里云 OSS ↔ 阿里云 Odoo 19 全部走国内高速链路（同区/内网可达），下载邮件附件和上传 Odoo 附件稳定不掉线。
- **双机职能隔离**：
  - **主机 1（AI 幕僚网关 + 文档处理主机）**：呼和浩特阿里云 ECS `firematrix`（2 核 4G，Ubuntu 24.04，60G 系统盘目前仅用约 16%，详见本地 `env/.env.ecs`）。该机当前跑着轻量官网 `firematrix-web`（端口 3000），本助理以独立 `systemd` 后台服务（系统用户 `wxagent`）运行，**不占用额外公网入站端口、不影响已有官网**。
  - **主机 2（业务数据中枢）**：阿里云 Odoo 19 生产主机（`https://erp.wissentek.com` / `erp.palmarytech.com`），只通过加密 HTTPS + Agent 专用 API Key 对外提供标准 XML-RPC / JSON-RPC 服务，解析大 PDF 产生的 CPU/内存峰值不会拖慢 Odoo 数据库。
  - **对象存储**：在呼和浩特或北京地域开通 1 个**阿里云私有 OSS Bucket** 存放全量原始消息与附件，解决 ECS 60G 磁盘长期扩容焦虑。

## 二、 上线前安全整改清单（必做）

在正式启动云端服务并存入公司聊天与邮件数据之前，必须先完成以下安全加固（根据本地 `env/.env.bailian` 与 `env/.env.ecs` 已有排查记录）：

1. **轮换百炼 API Key**：`env/.env.bailian` 中记录的旧 Key 曾出现在历史私有仓库记录里；请在阿里云百炼控制台（华北 2 北京地域）新建专用 Key（建议命名 `wechat-assistant-prod`），替换后删除旧 Key，并配置月度消费预警额度。
2. **加固 ECS `firematrix` 登录凭据**：为 `firematrix` 生成专用 SSH Ed25519 密钥，修改 `root` 密码后确认密钥登录稳定，再关闭 SSH 密码登录。
3. **环境变量与数据权限严格隔离**：
   - 所有真实密钥（企微 BotID/Secret、百炼 Key、Odoo API Key、工作邮箱 IMAP 授权码、OSS AccessKey）只写入服务器 `/etc/wechat-agent/env`（权限 `640`，属主 `root:wxagent`），**永远不进入 Git 仓库**；
   - 服务端应用日志（`journalctl`）仅输出消息 ID、处理状态、耗时和错误码，**严禁打印聊天正文、邮件正文与任何密钥**。
4. **Odoo 沙箱先行**：`ODOO_ALLOWED_DATABASES` 先锁定沙箱数据库（如 `prod_sandbox_demo`）跑通全部写入与回滚测试，通过后再放行生产数据库写权限。

## 三、 服务端环境变量模板 (`/etc/wechat-agent/env`)

以下为服务端配置文件标准模板（所有真实凭据仅在部署时填入服务器本地，切勿填入代码或文档）：

```ini
# --- 运行基础 ---
TZ=Asia/Shanghai
DATA_DIR=/opt/wechat-agent/data
LOG_LEVEL=INFO

# --- 1. 微信 / 企业微信通道（按所选通道二选一） ---
WECHAT_CHANNEL=wecom_ws               # wecom_ws（企微智能机器人长连接）或 openclaw_weixin
WECOM_BOT_ID=<企微智能机器人 BotID>
WECOM_BOT_SECRET=<企微智能机器人长连接 Secret>
SEGMENT_QUIET_SECONDS=60              # 逐条转发静默合并窗口（秒）

# --- 2. 阿里云百炼大模型 ---
DASHSCOPE_API_KEY=<新生成的百炼 API Key>
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_MODEL=qwen3.8-max
QWEN_SNAPSHOT_MODEL=qwen3.8-max-0902

# --- 3. 阿里云 Odoo 19 连接 ---
ODOO_URL=<Odoo 19 HTTPS 地址>
ODOO_DB=<目标数据库名，初期先用沙箱库>
ODOO_LOGIN=<Agent 专用操作邮箱>
ODOO_API_KEY=<Odoo Account Security 生成的 API Key>
ODOO_IDEA_PROJECT_NAME=CEO 想法与孵化池
ODOO_ALLOW_WRITES=true

# --- 4. 工作邮箱 IMAP（第二阶段启用） ---
IMAP_ENABLED=false
IMAP_HOST=<邮箱 IMAP 服务器地址，如 imap.qiye.aliyun.com>
IMAP_PORT=993
IMAP_USER=<工作邮箱账号>
IMAP_PASSWORD=<邮箱专用客户端授权码>
IMAP_POLL_INTERVAL_SECONDS=120

# --- 5. 阿里云 OSS 原件归档 ---
OSS_ENABLED=true
OSS_ENDPOINT=<如 https://oss-cn-huhehaote.aliyuncs.com>
OSS_BUCKET=<私有 Bucket 名称>
OSS_ACCESS_KEY_ID=<子账号 RAM AccessKey ID（仅限该 Bucket 读写）>
OSS_ACCESS_KEY_SECRET=<子账号 RAM AccessKey Secret>

# --- 6. 确认模式与每日简报 ---
CONFIRM_MODE=preview_card             # preview_card（回1确认）或 auto_with_undo（自动+可撤销）
DAILY_MORNING_DIGEST=08:30
DAILY_EVENING_DIGEST=18:00
```

## 四、 三阶段敏捷实施路线图

不一口气写几万行代码，每一阶段上线即刻带来实际减负效果：

### 第一阶段：微信 + 语音闪念 → 百炼单卡分拣 → Odoo 19 & 文档库（MVP，3～5 天）
- **交付目标**：你在个人微信里随手转发聊天、发文件、发语音想法，机器人发来 1 张预览卡，回 `1` 后自动归集进 Odoo 19（项目进展 / 待办 / `CEO 想法与孵化池`）并把附件规范命名存入 ECS 分类目录 + OSS。
- **关键动作**：
  1. 完成上述安全整改，在 `firematrix` 初始化 `/opt/wechat-agent/` 与 OSS Bucket；
  2. 打通微信入口并完成 **T1–T3 实测**（确认合并转发/逐条转发机制与发文件上限）；
  3. 接入百炼 `qwen3.8-max` + 数字保真硬核验，先连 Odoo 沙箱验证写入、挂附件与 `撤销` 回滚；
  4. 上线每日 18:00 待办与新增归档推送。

### 第二阶段：工作邮箱自动接入（第 2 周）
- **交付目标**：客户询盘、海外原厂英文技术邮件和 PDF 规格书**全自动进入幕僚流水线**，无需手动截图转发到微信。
- **关键动作**：
  1. 启用只读 IMAP 增量监听器与垃圾/验证码过滤规则；
  2. 接通 PDF（如 `pypdf` / `pymupdf`）、Word、Excel 按页文本提取与图片 OCR，入库 SQLite FTS5；
  3. 邮件正文中识别出的报价金额、交期变化自动与已有历史对照，修订/矛盾高亮推送微信确认。

### 第三阶段：Mac 本地目录自动同步 + 深度历史问答（第 3 周）
- **交付目标**：在电脑前打开 Finder / Obsidian 就能直接用所有自动分类好的文件；在微信里用一句话查跨微信、邮件与文档内页的历史细节。
- **关键动作**：
  1. 部署 Syncthing（经 Tailscale 专线）或 `rclone`，把 ECS `archive/` 自动镜像到办公室/家里 Mac 本地目录；
  2. 开放“带出处、带页码、带冲突提示”的只读工具问答循环；
  3. 根据使用 2～4 周后的手感，按需决定是否从“单卡确认（模式 A）”平滑切换到“高把握自动入库 + 异常确认（模式 B）”。

## 五、 开工前仅需确认的 3 个配置项

进入代码开发阶段前，只需拍板以下三项即可立刻动工：

1. **微信接入通道**：首选 **企业微信智能机器人长连接 + 微信插件**（最稳），还是 **OpenClaw + `@tencent-weixin/openclaw-weixin`**（个人微信主列表直聊）？
2. **默认确认手感**：启用 **模式 A**（每件事出 1 张预览卡，回 `1` 确认写入），还是 **模式 B**（高把握自动写入并回执，仅冲突/新建项目停下来问你）？
3. **目标工作邮箱服务商**：主力收发客户与原厂邮件的是哪家邮箱（如阿里企业邮、腾讯企业邮、微软 365 或自建邮件服务器）？
